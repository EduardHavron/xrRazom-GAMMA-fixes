# Спецификации (SDD)

Источник истины для поведения репозитория и каждого фикса. Код и тесты следуют спецификации:
сначала меняется спека, потом код, потом тесты, которые ссылаются на ID требований.

## Структура

```
specs/
  README.md                 этот файл: правила, шаблоны, реестр ID
  system/
    overview.md             общая картина: роли (хост/пир), потоки данных, глоссарий
    repo-layout.md          структура репозитория, pack.json, pack.txt, маркеры, .gitattributes
    publish.md              host/publish.ps1: секция MO2, 3-стороннее сравнение, догон, конфликты, коды выхода
    ci-release.md           GitHub Actions: проверки, сборка xrRazom_fixes.zip, релиз, уведомления Discord
    installer.md            installer/install.ps1: правила секции у получателя
    agent.md                agent/: режим пира, режим хоста, самообновление, планировщик
  fixes/
    <id>.md                 по одному файлу на фикс (имя файла = ID фикса)
```

## Идентификаторы требований

`<ОБЛАСТЬ>-<NNN>`, номера не переиспользуются (удалённое требование помечается `~~зачёркнуто~~ (удалено)`).

| Префикс | Документ |
|---|---|
| SYS | system/overview.md |
| REPO | system/repo-layout.md |
| PUB | system/publish.md |
| CI | system/ci-release.md |
| INS | system/installer.md |
| AGT | system/agent.md |
| FX-<КОД> | fixes/*.md (код фикса, напр. `FX-FETCH-003`) |

Каждое требование — одна проверяемая фраза с модальностью **ДОЛЖЕН / НЕ ДОЛЖЕН / МОЖЕТ**.
К требованию — критерии приёмки в виде *Дано / Когда / Тогда*, достаточно точные, чтобы написать по ним тест.
Пометка способа проверки: `[auto]` — покрывается автотестом (ссылка на тест появится позже), `[manual]` — только в игре/вручную.

## Шаблон system-документа

```markdown
# <Название>
Статус: действует | черновик        Код: `путь/к/файлу`

## Назначение
## Термины            (если нужны сверх overview.md)
## Входы и выходы     (файлы, параметры, переменные окружения, коды выхода)
## Требования
### PUB-001 <короткое имя>  [auto]
<Требование.>
- Дано … Когда … Тогда …
## Ошибки и граничные случаи
## Вне области
## Открытые вопросы / известные ограничения
```

## Шаблон спецификации фикса

```markdown
# FX-<КОД>: <название>
Статус: действует        Мод: `zz xrRazom Fix - ...`        Скрипт: `gamedata/scripts/<file>.script`
Где ставить: хост | пир | оба        Зависит от: <моды/версии>        Лог-маркер: `[XRRFIX] ...`

## Проблема            (симптом глазами игрока)
## Причина             (точный механизм в коде затронутых модов, со ссылками на файлы/функции)
## Решение             (что и куда патчится, точки перехвата)
## Требования
### FX-<КОД>-001 ...  [auto|manual]
- Дано … Когда … Тогда …
## Безопасность         (что происходит без зависимых модов, в соло, на хосте; идемпотентность)
## Вне области / известные ограничения
## Проверка в игре      (пошагово, что должно появиться в логе)
```
