# Структура репозитория и форматы данных
Статус: действует        Код: `.gitattributes`, `pack/pack.json`, `host/publish.ps1`, `.github/scripts/build_pack.py`, `installer/install.ps1`

## Назначение

Описывает, что лежит в репозитории `EduardHavron/xrRazom-GAMMA-fixes` (публичный, ветка `main`), кто пишет каждый файл,
форматы `pack/pack.json`, `pack.txt`, маркера `xrrfix_pack.txt`, правило хранения байт-в-байт и версионирование.
Термины — в `overview.md`.

## Входы и выходы

### Верхний уровень

| Путь | Что это | Кто пишет |
|---|---|---|
| `mods/<имя мода>/…` | Копии включённых модов секции (без верхнеуровневых `meta.ini`, `xrrfix_pack.txt`) | только `host/publish.ps1` (коммит) |
| `pack/pack.json` | Секция и упорядоченный список модов пакета | только `host/publish.ps1` |
| `host/publish.ps1`, `publish.bat`, `publish.ini` | Публикатор и его настройки по умолчанию | разработчик (вручную) |
| `installer/install.ps1`, `install.bat`, `README.txt` | Установщик (кладётся в zip релиза) | разработчик |
| `agent/*.ps1`, `*.bat`, `README.txt` | Фоновый агент (кладётся в zip релиза, самообновляется) | разработчик |
| `.github/workflows/release.yml` | CI: проверка, сборка, релиз, Discord | разработчик |
| `.github/scripts/build_pack.py` | Проверка `pack.json`/Lua/XML и сборка zip | разработчик |
| `specs/` | Спецификации SDD (источник истины) | разработчик |
| `tests/` | Автотесты (PowerShell 5.1, `tests/lib/assert.ps1`) | разработчик |
| `README.md`, `LICENSE`, `.gitattributes` | Обзор, лицензия, правило байт-в-байт | разработчик |

`.gitignore` в репозитории нет.

### `pack/pack.json`

```json
{
  "section": "xrRazom Sync",
  "mods": [
    "zz xrRazom Fix - Laser State",
    "zz Workshop Ammo Material Fix"
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `section` | непустая строка | имя секции MO2 (разделитель `<section>_separator`) |
| `mods` | непустой массив непустых строк | имена папок модов; порядок = приоритет MO2, первый — высший |

### `pack.txt` (корень zip релиза и временного пакета догона)

```
version=<версия>
profile=github
section=<section>

[mod] <имя 1>
  <первые 16 hex SHA-256>  <путь внутри мода через \>
[mod] <имя 2>
  …
```

UTF-8 без BOM, LF, завершается переводом строки. Установщик читает только `version=`, `section=` и строки `[mod] `
(их порядок = порядок установки/приоритет). Строки хэшей пишет только CI; во временном пакете догона их нет.

### Маркер `<папка мода>\xrrfix_pack.txt`

Одна строка `xrRazom fixes pack <версия>` (`<версия>` — версия релиза или `sync-<sha7>`). Пишется через
`Set-Content -Encoding UTF8` (PowerShell 5.1: UTF-8 с BOM, CRLF).

## Требования

### REPO-001 Состав `mods/` и `pack.json` пишет только publish  [auto]
Изменения в `mods/` и `pack/` ДОЛЖНЫ вноситься только `host/publish.ps1`; незакоммиченные правки в этих папках НЕ ДОЛЖНЫ
переживать запуск publish (он их сбрасывает как остатки прерванного запуска).
- Дано в рабочем дереве изменён файл `mods/A/x.script` и добавлен неотслеживаемый `pack/tmp.txt`. Когда запускается publish.
  Тогда до сравнения оба изменения отменены (файл = `HEAD`, `pack/tmp.txt` удалён), в выводе сообщение о сбросе.

### REPO-002 `mods/<имя>/` — точная копия без служебных файлов  [auto]
Папка `mods/<имя>/` ДОЛЖНА совпадать побайтно с папкой мода публикующего, за исключением верхнеуровневых `meta.ini` и
`xrrfix_pack.txt`, которых в репозитории быть НЕ ДОЛЖНО. Вложенные файлы с такими именами (например
`gamedata/meta.ini`) ДОЛЖНЫ публиковаться как обычные.
- Дано мод с `meta.ini`, `xrrfix_pack.txt`, `gamedata/scripts/a.script`, `gamedata/meta.ini`. Когда он опубликован.
  Тогда `git ls-tree -r HEAD mods/<имя>` содержит `gamedata/scripts/a.script` и `gamedata/meta.ini` и не содержит
  `mods/<имя>/meta.ini`, `mods/<имя>/xrrfix_pack.txt`.

### REPO-003 Схема `pack.json`  [auto]
`pack.json` ДОЛЖЕН быть JSON-объектом с непустой строкой `section` и непустым массивом `mods` из уникальных непустых строк,
не содержащих `/`, `\` и не равных `.`/`..`; для каждого имени ДОЛЖНА существовать непустая папка `mods/<имя>/`.
Нарушение ДОЛЖНО валить проверку CI (`build_pack.py validate`, код 1).
- Дано `pack.json` с `"mods": ["A", "A"]`. Когда выполняется `build_pack.py validate`. Тогда код 1 и ошибка
  `duplicate mod name 'A'`.
- Дано `"mods": []`. Тогда код 1 (`'mods' must be a non-empty array`).
- Дано имя `B` в списке, папки `mods/B/` нет. Тогда код 1.

### REPO-004 Порядок списка = приоритет MO2  [auto]
Порядок `mods` в `pack.json` ДОЛЖЕН совпадать с порядком строк секции в `modlist.txt` публикующего (сверху вниз,
первый — высший приоритет) с учётом слияния порядков из `publish.md`.
- Дано секция `+B`, `+A`, `+xrRazom Sync_separator` и ни B, ни A нет на GitHub. Когда первая публикация с `-Yes`.
  Тогда `mods` = `["B", "A"]`.

### REPO-005 Формат записи `pack.json`  [auto]
Publish ДОЛЖЕН писать `pack.json` в UTF-8 без BOM, с LF, отступами 2 (`section`, `mods`) и 4 (элементы), переводом строки
в конце, экранируя в строках только `"`, `\` и символы < U+0020 (`\uXXXX`); и ДОЛЖЕН перезаписывать файл только если
итоговый список или имя секции отличаются от `pack.json` в `HEAD`.
- Дано список и секция совпадают с `HEAD`, изменён только файл мода. Когда publish. Тогда `pack/pack.json` в коммите не изменён.
- Дано новый список `["A","B"]`, секция `xrRazom Sync`. Тогда байты файла:
  `{\n  "section": "xrRazom Sync",\n  "mods": [\n    "A",\n    "B"\n  ]\n}\n`.

### REPO-006 Чтение `pack.json` терпимо к BOM  [auto]
Читатели (`publish.ps1`, `build_pack.py`, шаг Discord в CI) ДОЛЖНЫ принимать `pack.json` с BOM UTF-8 и без него.
- Дано `pack.json` с BOM. Когда выполняются `build_pack.py validate` и publish. Тогда оба читают список без ошибки.

### REPO-007 Папки вне списка не раздаются  [auto]
Папка `mods/<имя>/`, отсутствующая в `pack.json`, НЕ ДОЛЖНА попадать в релиз и ДОЛЖНА считаться отсутствующей при
3-стороннем сравнении; CI ДОЛЖЕН выдать предупреждение (не ошибку).
- Дано `mods/C/` есть, в `pack.json` нет C. Когда `validate`. Тогда код 0 и предупреждение
  `mods/C/ is not listed in pack/pack.json and will NOT be released`; в zip нет `mods/C/`.

### REPO-008 Хранение байт-в-байт  [auto]
`.gitattributes` ДОЛЖЕН содержать правило `* -text` (никакой нормализации концов строк ни для какого файла), а все вызовы
git из publish ДОЛЖНЫ выполняться с `-c core.autocrlf=false -c core.quotepath=false`. Причина: xrRazom сравнивает файлы
модов хоста и пира побайтно; любая конверсия CRLF/LF при checkout у одного из игроков ломает вход.
- Дано файл мода с CRLF и клон с глобальным `core.autocrlf=true`. Когда файл опубликован, а затем получен другим клоном
  (fetch + fast-forward). Тогда blob id в репозитории равен `git hash-object --no-filters` исходного файла, а файл в рабочем
  дереве второго клона побайтно равен исходному.

### REPO-009 Формат `pack.txt`  [auto]
`pack.txt` ДОЛЖЕН соответствовать формату из раздела «Входы и выходы»: первые строки `version=`, `profile=github`,
`section=`, пустая строка, затем для каждого мода списка по порядку строка `[mod] <имя>`; в zip CI после неё — строки
`  <sha256[:16]>  <путь с \>`, отсортированные по пути с `\`.
- Дано `pack.json` = `["B","A"]`. Когда CI собирает версию `2026.10.13-5`. Тогда `pack.txt` начинается с
  `version=2026.10.13-5\nprofile=github\nsection=xrRazom Sync\n\n[mod] B\n`, и `[mod] A` идёт после хэшей B.

### REPO-010 Маркер  [auto]
Маркер `xrrfix_pack.txt` ДОЛЖЕН писаться установщиком в каждую установленную папку мода, а publish — в локальные папки
модов, которые догон убирает из секции; маркер НЕ ДОЛЖЕН коммититься и НЕ ДОЛЖЕН влиять на сравнение содержимого.
- Дано в локальной папке мода появился/изменился только `xrrfix_pack.txt`. Когда publish. Тогда мод в статусе «совпадает»,
  коммита нет («Изменений нет»).

### REPO-011 `meta.ini` не публикуется и сохраняется у публикующего  [auto]
Верхнеуровневый `meta.ini` НЕ ДОЛЖЕН публиковаться и сравниваться; при догоне мода с GitHub локальный `meta.ini` этого мода
ДОЛЖЕН сохраниться.
- Дано у хоста `mods\A\meta.ini` с `modid=123`, друг опубликовал новую A. Когда хост делает догон. Тогда файлы A = версия друга,
  `meta.ini` хоста прежний.

### REPO-012 Версия и тег релиза  [auto]
Версия релиза ДОЛЖНА иметь вид `ГГГГ.ММ.ДД-N` (дата UTC запуска CI, N = `github.run_number`), тег — `v<версия>`,
заголовок — `xrRazom fixes <версия>`, единственный ассет — `xrRazom_fixes.zip`, релиз помечается как latest.
- Дано запуск workflow №7 13.10.2026 UTC. Когда релиз создан. Тогда тег `v2026.10.13-7`.

### REPO-013 Коммиты publish трогают только `mods/` и `pack/`  [auto]
Коммит, созданный publish, ДОЛЖЕН содержать изменения только путей `mods/**` и `pack/**`, даже если в индексе есть другие
подготовленные изменения.
- Дано в индексе подготовлено изменение `README.md`, локально изменён мод A. Когда publish. Тогда в новом коммите только
  `mods/A/...`; `README.md` остаётся подготовленным, но не закоммиченным.

### REPO-014 Что никогда не коммитится  [auto]
В репозитории НЕ ДОЛЖНО быть: верхнеуровневых `mods/*/meta.ini`, файлов `xrrfix_pack.txt`, артефактов сборки (`dist/`,
`xrRazom_fixes.zip`, `notes.md`), файлов профилей MO2 (`modlist.txt`, `*.xrrfix.bak`), состояния агента
(`%LOCALAPPDATA%\xrrfix\*`: `gamma_root.txt`, `installed_version.txt`, `repo_root.txt`, логи), секретов (вебхуки, токены).
- Дано `git ls-files`. Когда проверяем шаблоны выше. Тогда совпадений нет.

### REPO-015 Кодировки служебных файлов  [auto]
`.ps1` и `.txt` с кириллицей, а также `publish.ini` ДОЛЖНЫ храниться в UTF-8 с BOM (PowerShell 5.1 иначе читает их в ANSI);
`.bat` ДОЛЖНЫ быть ASCII.
- Дано файлы `host/*.ps1`, `installer/*.ps1`, `agent/*.ps1`, `host/publish.ini`. Когда читаем первые 3 байта. Тогда `EF BB BF`.
- Дано `*.bat`. Тогда все байты < 0x80.

### REPO-016 Изменения `specs/`, `tests/`, `README.md` не выпускают релиз  [auto]
Push, меняющий только пути вне `mods/`, `pack/`, `installer/`, `agent/`, `.github/workflows/release.yml`,
`.github/scripts/`, НЕ ДОЛЖЕН запускать сборку релиза.
- Дано коммит меняет только `specs/system/publish.md`. Когда он запушен в `main`. Тогда workflow `release.yml` не стартует
  (проверяется по фильтру `on.push.paths`).

## Ошибки и граничные случаи

- Пустая папка мода: git не хранит пустые папки; мод из списка без файлов имеет пустой ключ содержимого, а CI валит сборку
  (`mods/<имя>/ is empty`).
- Имена модов, различающиеся только регистром: Windows и сравнения PowerShell (`-contains`, хеш-таблицы) нечувствительны
  к регистру, `List.Contains` — чувствителен; такие имена не поддерживаются.
- Скрытые файлы в папке мода (`desktop.ini`, `Thumbs.db`) публикуются и сравниваются как обычные.

## Вне области

- Логика сравнения и публикации — `publish.md`; сборка и релиз — `ci-release.md`; правила секции у получателя — `installer.md`.

## Открытые вопросы / известные ограничения

1. CONTRACT.md: «`mods/<name>/` — exact copies … (only gamedata/, meta.ini etc.)»; фактически `meta.ini` верхнего уровня
   из репозитория исключается (код главнее).
2. Все `.bat` (`host/publish.bat`, `installer/install.bat`, `agent/*.bat`) хранятся в ASCII + CRLF (проверено по
   `git show HEAD:<file>`); `* -text` сохраняет CRLF как есть. REPO-015 при этом CRLF явно не требует — кандидат на ужесточение.
3. `.gitignore` нет: ничто технически не мешает закоммитить `dist/` или `xrRazom_fixes.zip` вручную; REPO-014 проверяется тестом.
4. `pack.json` с пустым `mods` publish записать может (см. `publish.md`), но CI такой коммит отвергнет — релиза не будет.
5. Имена модов с запятой ломают разбор `XRRFIX_SYNC_*` и `-TakeRemote/-TakeLocal` (запятая — разделитель).
6. Версия в README записана как `vГГГГ.ММ.ДД-N` без пояснения, что N сквозной и не сбрасывается по дням.
