# Агент автообновления
Статус: действует        Код: `agent/xrrfix_agent.ps1`, `agent/setup_agent.ps1`, `agent/setup_agent.bat`, `agent/uninstall_agent.ps1`, `agent/uninstall_agent.bat`, `agent/README.txt`

## Назначение

Фоновый агент держит фиксы xrRazom в MO2 игрока актуальными без участия человека. Его раз в 10 минут
запускает Планировщик задач от имени пользователя, без прав администратора.

- **Режим пира** (обычный). Агент опрашивает GitHub `releases/latest`, скачивает `xrRazom_fixes.zip`
  и ставит его через `install.ps1 -NoWait` (см. installer.md). Пока запущены MO2 или игра, установка откладывается.
- **Режим хоста**. На ПК есть git-клон `EduardHavron/xrRazom-GAMMA-fixes`. Агент не качает релизы, а запускает
  `host\publish.ps1 -SyncOnly -NoWait -NoPrompt` (см. publish.md): так чужие публикации попадают в MO2 хоста.
- **Самообновление** (оба режима). В конце запуска агент заменяет свои файлы в `<home>\agent`
  новыми: из папки `agent\` релиза или из `<клон>\agent`.

Установщик `setup_agent` копирует агент, определяет папку GAMMA и режим, регистрирует задачу,
создаёт ярлык и делает первый запуск. `uninstall_agent` всё это отменяет. Установленные моды он не трогает.

## Термины

| Термин | Значение |
|---|---|
| `<home>` | папка состояния агента: `%XRRFIX_HOME%`, если задана, иначе `%LOCALAPPDATA%\xrrfix` |
| тест-режим | `XRRFIX_HOME` задана и не совпадает с `%LOCALAPPDATA%\xrrfix` (сравнение без завершающего `\`) |
| корень GAMMA | папка, где есть файл/папка `ModOrganizer.exe` и папка `mods` (`Test-Root`) |
| клон | папка с `.git`, файлами `host\publish.ps1` и `agent\xrrfix_agent.ps1`, у которой вывод `git remote get-url origin` содержит `EduardHavron/xrRazom-GAMMA-fixes` |
| блокирующие процессы | процессы, при которых установка откладывается: `ModOrganizer`, `Anomaly*` (или список из `XRRFIX_BLOCK_PROCS`) |
| запуск | один вызов `xrrfix_agent.ps1` (по расписанию, с ярлыка или из setup) |
| интерактивный запуск | запуск с `-Interactive` |

## Входы и выходы

### Параметры

| Скрипт | Параметр | Действие |
|---|---|---|
| `xrrfix_agent.ps1` | `-Force` | переустановить, даже если версия уже стоит; игнорировать ETag и паузу после неудачи |
| | `-Interactive` | дублировать ход работы в консоль; уведомления о неудаче показывать всегда |
| | `-PauseAtEnd` | в конце ждать Enter |
| `setup_agent.ps1` | `-DryRun` | ничего не менять, только показать план |
| | `-GammaRoot <p>` | корень GAMMA без поиска и вопросов |
| | `-NoRun` | не запускать первую проверку |
| | `-Shortcut` / `-NoShortcut` | создать ярлык без вопроса / не создавать |
| | `-PlainPowerShell` | задача запускает `powershell.exe` напрямую, без `conhost --headless` |
| `uninstall_agent.ps1` | `-DryRun` | только показать план |
| | `-RemoveFiles` / `-KeepFiles` | удалить файлы агента без вопроса / не удалять |

`setup_agent.bat` и `uninstall_agent.bat` передают аргументы (`%*`) в `.ps1` через
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File` и после этого делают `pause`.

### Переменные окружения (для тестов)

| Переменная | Действие |
|---|---|
| `XRRFIX_HOME` | заменяет `<home>`; включает тест-режим; setup и uninstall при этом не трогают Планировщик |
| `XRRFIX_API` | URL вместо `https://api.github.com/repos/EduardHavron/xrRazom-GAMMA-fixes/releases/latest` |
| `XRRFIX_REPO` | путь к клону: поиск не выполняется, `repo_root.txt` не пишется. Значение `none` означает «всегда режим пира» |
| `XRRFIX_BLOCK_PROCS` | блокирующие процессы через запятую (имена для `Get-Process -Name`, допускаются маски). Через окружение наследуется в `install.ps1` и `publish.ps1` |
| `XRRFIX_NO_NOTIFY=1` | не показывать всплывающие уведомления |

### Файлы состояния в `<home>`

Все текстовые файлы агент пишет в UTF-8 с BOM и CRLF. Читается только первая строка, с обрезкой пробелов.

| Файл | Кто пишет | Смысл |
|---|---|---|
| `gamma_root.txt` | setup, `install.ps1` | корень GAMMA; общий с инсталлятором |
| `installed_version.txt` | агент (пир) | версия последней успешной установки (тег без `v`) |
| `failed_version.txt` | агент (пир); setup удаляет | ключ последней неудачи: версия или `noroot`. Дата изменения задаёт паузу повтора |
| `api_etag.txt` | агент (пир) | ETag последнего ответа 200 |
| `api_latest.json` | агент (пир) | тело последнего ответа 200 (UTF-8 без BOM) |
| `repo_root.txt` | setup, агент | кэш пути к клону (режим хоста) |
| `mode.txt` | агент | ключ последнего режима: `host\|<путь>`, `peer` или `peer\|<пояснение>` |
| `host_state.txt` | агент (хост); setup удаляет | ключ последнего уведомления хоста: `conflict <sha>` или `error <sha>` |
| `sync_last.log` | агент (хост) | полный вывод последнего `publish.ps1 -SyncOnly` |
| `agent.log` | агент | журнал (обрезается) |
| `dl\` | агент (пир) | временные загрузки и распаковка |
| `agent\` | setup, самообновление | установленная копия файлов агента; отсюда задача запускает `xrrfix_agent.ps1` |

### Интерфейс `publish.ps1 -SyncOnly` (используемая часть)

- Коды выхода: `0` — ок, `1` — ошибка, `2` — отложено (MO2/игра запущены, `publish` уже идёт или инсталлятор вернул 2), `3` — конфликт.
- Строка `XRRFIX_SYNC_RESULT: installed=<n> mods=<имя1,имя2,...>` печатается при коде 0.
- Строка `XRRFIX_SYNC_CONFLICT: mods=<имена через запятую>` печатается при коде 3. Если порядок модов изменён с обеих сторон, в список входит `(порядок модов)`.

### Коды выхода агента

| Код | Когда |
|---|---|
| 0 | всё актуально, отложено, нет связи, нет релиза, установлено, синхронизировано; также если агент уже работает |
| 1 | неудача установки или настройки (пир), ошибка синхронизации (хост), непредвиденное исключение |
| 3 | конфликт синхронизации (хост) |

## Требования

*Установка (`setup_agent`)*

### AGT-001 Копирование файлов агента  [auto]
Setup ДОЛЖЕН скопировать в `<home>\agent` файлы `xrrfix_agent.ps1`, `setup_agent.ps1`, `setup_agent.bat`,
`uninstall_agent.ps1`, `uninstall_agent.bat` и `README.txt` из своей папки с перезаписью, а затем снять с них
пометку «загружено из интернета» (`Unblock-File`). Отсутствующие файлы, кроме `xrrfix_agent.ps1`, пропускаются.
- Дано: папка-источник со всеми шестью файлами; `XRRFIX_HOME=<tmp>\xrrfix`. Когда: `setup_agent.ps1 -GammaRoot <fake> -NoRun -NoShortcut`. Тогда: все шесть файлов лежат в `<tmp>\xrrfix\agent` и побайтно совпадают с источником.
- Дано: в источнике нет `xrrfix_agent.ps1`. Когда: setup запущен. Тогда: он падает с ошибкой `Не найден xrrfix_agent.ps1 рядом с setup_agent.ps1`, и `<home>\agent` не создаётся.
- Дано: setup запущен из самой `<home>\agent`. Когда: шаг 1. Тогда: копирования нет, выводится `Файлы агента уже в <home>\agent`.

### AGT-002 Определение корня GAMMA  [auto]
Setup ДОЛЖЕН определить корень GAMMA в таком порядке:
1. `-GammaRoot`, если он задан. Если папка не корень GAMMA — ошибка `В '<p>' нет ModOrganizer.exe и папки mods`.
2. `<home>\gamma_root.txt`, затем `%LOCALAPPDATA%\xrrfix\gamma_root.txt`, если строка в файле — корень GAMMA.
3. Подъём по родителям от папки setup.
4. `<диск>:\{GAMMA, G.A.M.M.A, Gamma, Games\GAMMA, Games\Gamma, Games\G.A.M.M.A, Stalker\GAMMA}` на всех файловых дисках.

Найденный без `-GammaRoot` путь ДОЛЖЕН быть подтверждён вопросом `Это она? [Д/н]`. При ответе «нет» или если
ничего не найдено, открывается диалог выбора папки, который повторяется, пока не выбран корень GAMMA или диалог не отменён.
Отмена ДОЛЖНА прерывать setup с ошибкой `Папка GAMMA не выбрана - настройка прервана.`
- Дано: `-GammaRoot` указывает на папку без `mods`. Когда: setup. Тогда: исключение, `gamma_root.txt` не создан.
- Дано: `<home>\gamma_root.txt` указывает на корректный fake-GAMMA, на stdin ответ «д». Когда: setup без `-GammaRoot`. Тогда: используется этот путь, диалог не открывается.
- Дано: setup лежит в `<fakeGamma>\tools\agent\`, сохранённых путей нет. Когда: setup. Тогда: найден `<fakeGamma>`.

### AGT-003 Сохранение корня GAMMA  [auto]
Если нет `-DryRun`, setup ДОЛЖЕН записать корень в `<home>\gamma_root.txt` (UTF-8) и удалить `<home>\failed_version.txt`,
чтобы следующий запуск агента сразу повторил неудавшуюся установку.
- Дано: в `<home>` есть `failed_version.txt` со значением `noroot`. Когда: `setup -GammaRoot <fake> -NoRun -NoShortcut`. Тогда: первая строка `gamma_root.txt` равна `<fake>` (полный путь), а `failed_version.txt` отсутствует.

### AGT-004 Определение режима при установке  [auto]
Setup ДОЛЖЕН искать клон среди кандидатов в таком порядке: `XRRFIX_REPO`, если задан (`none` означает «клона нет»);
иначе родитель папки setup, путь из `repo_root.txt`, непосредственные подпапки корня GAMMA и подпапки его родителя.
Клоном считается первый кандидат, который подходит по файлам и чей `origin` содержит маркер (см. AGT-013).
Если клон найден, setup ДОЛЖЕН вывести `Режим: ХОСТ - клон репозитория <путь>`, записать путь в `repo_root.txt` и удалить
`host_state.txt`. Если не найден — вывести `Режим: обычный - установка релизов с GitHub.` и удалить существующий `repo_root.txt`.
Если клон найден, но `git` нет в PATH, ДОЛЖНО выводиться предупреждение и выбираться обычный режим.
- Дано: временный клон, у которого `origin` = `https://github.com/EduardHavron/xrRazom-GAMMA-fixes.git`, и setup запущен из его `agent\`. Когда: setup. Тогда: `repo_root.txt` содержит полный путь клона.
- Дано: тот же клон с `origin` = `https://example.com/other.git`. Когда: setup. Тогда: печатается строка `... origin '...' не EduardHavron/xrRazom-GAMMA-fixes, пропуск.`, режим обычный, `repo_root.txt` удалён.
- Дано: `XRRFIX_REPO=none`. Когда: setup из клона. Тогда: режим обычный.

### AGT-005 Регистрация задачи  [manual]
Если нет ни `-DryRun`, ни тест-режима, setup ДОЛЖЕН зарегистрировать (с перезаписью) задачу `xrRazom fixes updater` с такими параметрами:
- действие `conhost.exe --headless "<PSHOME>\powershell.exe" -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "<home>\agent\xrrfix_agent.ps1"`.
  `powershell.exe` с теми же аргументами запускается напрямую, если задан `-PlainPowerShell`, сборка Windows < 19041 или нет `%SystemRoot%\System32\conhost.exe`;
- триггеры: при входе пользователя с задержкой 1 мин; однократно через 1 мин от момента setup с повтором каждые 10 мин без ограничения длительности;
- субъект: текущий пользователь `<USERDOMAIN>\<USERNAME>`, `LogonType Interactive`, `RunLevel Limited`;
- настройки: `MultipleInstances IgnoreNew`, запуск и работа от батареи, `StartWhenAvailable`, `ExecutionTimeLimit` 15 мин.
- Дано: чистая учётная запись Windows 10 2004+ без прав администратора. Когда: `setup_agent.bat`. Тогда: в Планировщике есть задача с указанными триггерами и действием, состояние «Готово», запуск не требует пароля.
- Дано: задача зарегистрирована. Когда: пользователь играет в полноэкранном режиме и срабатывает триггер. Тогда: окно консоли не появляется, игра не теряет фокус.

### AGT-006 Запасной путь через schtasks  [manual]
Если `Register-ScheduledTask` выбросил исключение, setup ДОЛЖЕН вывести предупреждение и создать задачу командой
`schtasks.exe /Create /TN "xrRazom fixes updater" /SC MINUTE /MO 10 /IT /F /TR "<короткая команда>"`.
В команде exe указаны короткими именами (`conhost.exe --headless powershell.exe ...` или `powershell.exe ...`), чтобы уложиться в лимит `/TR` в 261 символ.
Если schtasks вернул не 0, setup ДОЛЖЕН вывести `Не удалось создать задачу. Обновляйте вручную ярлыком ...` и продолжить работу (ярлык, первый запуск).
- Дано: служба Планировщика недоступна для cmdlet'ов (смоделировать на тестовой ВМ). Когда: setup. Тогда: создана задача с одним триггером «каждые 10 минут», setup доходит до `Готово.`

### AGT-007 DryRun и тест-режим установки  [auto]
При `-DryRun` или в тест-режиме setup НЕ ДОЛЖЕН регистрировать задачу. Вместо этого он ДОЛЖЕН собрать её определение
(`New-ScheduledTask`) и вывести триггеры, субъект и настройки, а также строку запасной команды schtasks.
При `-DryRun` setup также НЕ ДОЛЖЕН копировать файлы, писать `gamma_root.txt` и `repo_root.txt`, удалять файлы, создавать ярлык
и запускать агент. В конце он ДОЛЖЕН завершиться с кодом 0 после строки `[DryRun] запустил бы: <home>\agent\xrrfix_agent.ps1 -Interactive`.
- Дано: пустой `<tmp>\xrrfix` как `XRRFIX_HOME`. Когда: `setup -DryRun -GammaRoot <fake>`. Тогда: `<tmp>\xrrfix` остаётся пустым (или не создан), код 0, в выводе есть `MultipleInstances=IgnoreNew` и `/SC MINUTE /MO 10`.
- Дано: `XRRFIX_HOME=<tmp>\xrrfix` без `-DryRun`. Когда: `setup -GammaRoot <fake> -NoRun -NoShortcut`. Тогда: файлы скопированы, `Get-ScheduledTask 'xrRazom fixes updater'` не изменился.

### AGT-008 Ярлык ручного обновления  [manual]
Setup ДОЛЖЕН создать ярлык `<Рабочий стол>\Обновить фиксы xrRazom.lnk`, если задан `-Shortcut` или если пользователь
согласился на вопрос (по умолчанию «да»). Вопрос не задаётся при `-NoShortcut` и при `-DryRun`.
Параметры ярлыка: цель `<PSHOME>\powershell.exe`, аргументы `-NoProfile -ExecutionPolicy Bypass -File "<home>\agent\xrrfix_agent.ps1" -Force -Interactive -PauseAtEnd`,
рабочая папка `<home>\agent`.
- Дано: `-Shortcut`. Когда: setup. Тогда: ярлык существует, его запуск открывает консоль с ходом работы и ждёт Enter.

### AGT-009 Первая проверка  [auto]
Без `-NoRun` и `-DryRun` setup ДОЛЖЕН синхронно запустить `<home>\agent\xrrfix_agent.ps1 -Interactive` (без `-Force`)
через `powershell.exe -NoProfile -ExecutionPolicy Bypass`. Затем он выводит `Готово. ...` и путь к `agent.log`.
- Дано: локальный HTTP-сервер с релизом, `XRRFIX_API` указывает на него, `XRRFIX_BLOCK_PROCS=__none__`, `XRRFIX_NO_NOTIFY=1`. Когда: `setup -GammaRoot <fake> -NoShortcut`. Тогда: после выхода из setup `installed_version.txt` содержит версию релиза.

*Каждый запуск: общее*

### AGT-010 Папка состояния  [auto]
Агент ДОЛЖЕН использовать `<home>` и создавать его в начале работы (`Main`), если его нет.
В тест-режиме первой записью запуска в журнале ДОЛЖНА быть строка `[тест] XRRFIX_HOME=<home> API=<url> REPO=<XRRFIX_REPO>`.
- Дано: `XRRFIX_HOME=<tmp>\new\xrrfix` (не существует), `XRRFIX_REPO=none`, API недоступен. Когда: запуск. Тогда: папка создана, в `agent.log` есть строка `[тест] ...`, код 0.

### AGT-011 Единственный экземпляр  [auto]
Агент ДОЛЖЕН работать в одном экземпляре на `<home>`. Для этого используется мьютекс `Local\xrrfix_agent_<home в нижнем регистре без завершающего \, где каждый символ не из [a-z0-9] заменён на _>`.
Если мьютекс занят, агент ДОЛЖЕН сразу выйти с кодом 0: ничего не писать в журнал, не трогать состояние и не самообновляться.
При `-Interactive` он выводит `Агент уже работает, попробуйте через минуту.` (а с `-PauseAtEnd` ждёт Enter).
Брошенный мьютекс (`AbandonedMutexException`) ДОЛЖЕН считаться захваченным.
- Дано: тестовый процесс держит мьютекс с этим именем. Когда: запуск агента с тем же `XRRFIX_HOME`. Тогда: код 0, `agent.log` не изменился.
- Дано: тот же мьютекс занят. Когда: запуск с другим `XRRFIX_HOME`. Тогда: агент работает как обычно.

### AGT-012 Поиск клона при каждом запуске  [auto]
При каждом запуске агент ДОЛЖЕН заново выбирать режим через поиск клона:
- `XRRFIX_REPO=none` — клона нет, режим пира;
- `XRRFIX_REPO=<путь>` — проверяется только этот путь;
- иначе кандидаты по порядку: путь из `repo_root.txt`, родитель папки скрипта, непосредственные подпапки корня из `gamma_root.txt`
  и подпапки его родителя (если корень существует).

Повторы среди кандидатов отбрасываются без учёта регистра и завершающего `\`. Клоном становится первый кандидат,
который подходит по файлам и по `origin` (AGT-013).
- Дано: `gamma_root.txt` = `<sb>\Gamma`, клон лежит в `<sb>\repo`, `repo_root.txt` нет. Когда: запуск. Тогда: режим хоста с `<sb>\repo`.
- Дано: `XRRFIX_REPO=none` и клон рядом с GAMMA. Когда: запуск. Тогда: режим пира, `publish.ps1` не запускается.
- Дано: `XRRFIX_REPO=<папка без .git>`. Когда: запуск. Тогда: режим пира, в журнале `Обычный режим (релизы GitHub): XRRFIX_REPO='<папка>' - не клон репозитория.`

### AGT-013 Признаки клона  [auto]
Кандидат ДОЛЖЕН считаться клоном, только если выполнены все условия:
- существует `.git` (папка или файл);
- `host\publish.ps1` и `agent\xrrfix_agent.ps1` — файлы;
- `git -C <путь> remote get-url origin` завершился с кодом 0 за 60 с;
- вывод этой команды содержит `EduardHavron/xrRazom-GAMMA-fixes` (без учёта регистра).

`git` запускается без окна и с `GIT_TERMINAL_PROMPT=0`.
Если ни один кандидат, подходящий по файлам, не прошёл проверку `origin`, ДОЛЖЕН выбираться режим пира
с пояснением `у <первый кандидат> origin не EduardHavron/xrRazom-GAMMA-fixes.`

### AGT-040 Что и когда обновляется  [auto]
Самообновление ДОЛЖНО пропускаться, если в источнике нет `xrrfix_agent.ps1`, если нет `<home>\agent` или если источник и `<home>\agent` — одна папка.
Иначе обновляются только файлы верхнего уровня источника с расширениями `.ps1`, `.bat` и `.txt`, у которых нет копии в `<home>\agent`
или отличается SHA-256. Файлы, которых нет в источнике, из `<home>\agent` НЕ ДОЛЖНЫ удаляться.
После копирования с каждого файла снимается пометка «из интернета». В журнал пишется `Агент обновлён из <источник>: <имена через , >`.
- Дано: в источнике изменён только `uninstall_agent.ps1` и добавлен `extra.txt`. Когда: запуск. Тогда: скопированы ровно эти два файла, `xrrfix_agent.ps1` в `<home>\agent` не тронут (mtime прежний).
- Дано: `<home>\agent` не существует (агент запущен не из setup). Когда: запуск хоста. Тогда: ничего не копируется.
- Дано: все файлы совпадают. Когда: запуск. Тогда: строки `Агент обновлён` нет.

### AGT-041 Проверка синтаксиса перед заменой  [auto]
Перед копированием агент ДОЛЖЕН разобрать парсером PowerShell каждый изменённый `.ps1`. Если хотя бы в одном есть ошибка синтаксиса,
не копируется ни один файл, а в журнал пишется `Агент НЕ обновлён: ошибка синтаксиса в <файл>: <сообщение>`.
- Дано: в источнике изменены `README.txt` и `xrrfix_agent.ps1` с незакрытой `{`. Когда: запуск. Тогда: оба файла в `<home>\agent` прежние, строка об ошибке в журнале есть.

### AGT-042 Время самообновления  [auto]
Самообновление ДОЛЖНО выполняться в блоке `finally` после окончания основной работы, в том числе после непредвиденного исключения,
и до очистки `dl\`. Исключение при самообновлении пишется в журнал (`Самообновление не удалось: ...`) и не меняет код выхода.
Задача продолжает вызывать `<home>\agent\xrrfix_agent.ps1`: имя и путь файла не меняются.
- Дано: пир, успешная установка, в zip новый агент. Когда: запуск. Тогда: `<home>\agent\xrrfix_agent.ps1` совпадает с файлом из zip, а `dl\` после выхода пуст.

*Уведомления*

### AGT-043 Вид уведомления  [manual]
Уведомление ДОЛЖНО показываться всплывающей подсказкой значка в трее (`NotifyIcon`, подсказка значка `xrRazom fixes`).
Иконка «Информация» — для успеха, «Предупреждение» — для ошибок и конфликтов. Текст длиннее 250 символов обрезается до 247 + `...`.
Подсказка висит около 6 с, затем значок убирается. Если показать не удалось, в журнал пишется `уведомление не показано: <сообщение>`, а работа продолжается.
- Дано: задача в Планировщике, вышел новый релиз. Когда: срабатывает триггер. Тогда: в трее на ~6 с появляется подсказка `Фиксы xrRazom обновлены до <ver>`, значок затем исчезает, окна консоли нет.

### AGT-044 Отключение уведомлений  [auto]
При `XRRFIX_NO_NOTIFY=1` агент НЕ ДОЛЖЕН показывать уведомления. В тест-режиме вместо уведомления ДОЛЖНА писаться строка
`[тест] уведомление: <заголовок> | <текст>`. При `-Interactive` каждое уведомление также выводится в консоль как `[<заголовок>] <текст>`.
- Дано: `XRRFIX_NO_NOTIFY=1`, тест-режим, успешная установка. Когда: запуск. Тогда: в журнале строка `[тест] уведомление: xrRazom fixes | Фиксы xrRazom обновлены до ...`.

### AGT-045 Нет уведомления, когда нечего сообщать  [auto]
Агент НЕ ДОЛЖЕН показывать уведомления, если версия актуальна, если установка или синхронизация отложены, если нет связи, нет релиза или нет ассета,
если не удалось скачать файл или если синхронизация завершилась с `n` = 0.
- Дано: по одному прогону на каждый перечисленный случай с `XRRFIX_NO_NOTIFY=1` в тест-режиме. Когда: запуск. Тогда: строк `[тест] уведомление` нет.

### AGT-046 Однократное уведомление о неудаче пира  [auto]
При неудаче в режиме пира (AGT-023, AGT-026, AGT-030) агент ДОЛЖЕН прочитать прежний ключ из `failed_version.txt`, записать новый ключ
(версию или `noroot`) и тем самым обновить дату изменения файла. Уведомление показывается, только если ключ изменился или запуск интерактивный.
- Дано: `failed_version.txt` = V, установка V снова неудачна (пауза истекла). Когда: запуск без `-Interactive`. Тогда: уведомления нет, mtime файла обновлён.
- Дано: то же. Когда: запуск с ярлыка (`-Force -Interactive`). Тогда: уведомление показано.

*Журнал, коды выхода, окна*

### AGT-047 Формат журнала  [auto]
Каждая запись `agent.log` ДОЛЖНА быть строкой `yyyy-MM-dd HH:mm:ss <сообщение>` с CRLF в UTF-8. Если записать не удалось, это игнорируется.
При `-Interactive` сообщение дублируется в консоль.
- Дано: любой запуск, который пишет в журнал. Когда: разбор `agent.log`. Тогда: каждая строка соответствует `^\d{4}-\d\d-\d\d \d\d:\d\d:\d\d `, кроме строк многострочных сообщений об исключениях.

### AGT-048 Обрезка журнала  [auto]
В конце каждого запуска, захватившего мьютекс, агент ДОЛЖЕН сокращать `agent.log` до последних 500 строк, если в нём больше 600 строк.
- Дано: `agent.log` из 700 строк. Когда: запуск (любой). Тогда: после запуска в файле ровно 500 строк, последняя строка — последняя запись этого запуска.
- Дано: 599 строк, тест-режим с актуальной версией (запуск добавляет только строку `[тест] ...`). Когда: запуск. Тогда: 600 строк, обрезки нет.

### AGT-049 Коды выхода и непредвиденные ошибки  [auto]
Агент ДОЛЖЕН завершаться с кодами по таблице «Коды выхода агента». При необработанном исключении в основной работе он ДОЛЖЕН
записать `Непредвиденная ошибка: <сообщение> <стек>`, выполнить самообновление (если источник уже выбран), обрезать журнал, освободить мьютекс
и выйти с кодом 1. С `-Interactive` в конце выводится путь к журналу, с `-PauseAtEnd` — ожидание Enter.
- Дано: `api_latest.json` повреждён, `api_etag.txt` есть, сервер отвечает 304. Когда: запуск. Тогда: код 1, в журнале `Непредвиденная ошибка`, мьютекс свободен (следующий запуск работает).

### AGT-050 Без окон в фоне  [manual]
Дочерние процессы агента (`powershell.exe` для install/publish, `git`) ДОЛЖНЫ запускаться без окна (`CreateNoWindow`).
Запуск по расписанию в режиме `conhost --headless` НЕ ДОЛЖЕН создавать видимых окон и отнимать фокус у полноэкранной игры.
- Дано: игра в эксклюзивном полноэкранном режиме, задача срабатывает и в режиме хоста выполняет синхронизацию. Когда: проходит 10 мин. Тогда: игра не сворачивается, окна консоли и git не появляются.

*Удаление (`uninstall_agent`)*

### AGT-051 Снятие задачи и ярлыка  [manual]
Без `-DryRun` и вне тест-режима uninstall ДОЛЖЕН удалить задачу `xrRazom fixes updater`: через `Unregister-ScheduledTask`, а если не вышло —
через `schtasks /Delete /TN ... /F`. Если задачу не видит `Get-ScheduledTask`, но видит `schtasks /Query` — тоже через `schtasks /Delete`.
Иначе выводится `Задачи нет - пропуск.` Ярлык `Обновить фиксы xrRazom.lnk` на рабочем столе ДОЛЖЕН удаляться, если он есть.
`uninstall_agent.bat` записан одной строкой, чтобы доработать, даже если его собственный файл удалят во время работы.
- Дано: задача и ярлык созданы setup. Когда: `<home>\agent\uninstall_agent.bat`, ответ «н». Тогда: задачи и ярлыка нет, окно доходит до `pause` без ошибок cmd.

### AGT-052 Удаление файлов агента  [auto]
Uninstall ДОЛЖЕН удалять файлы агента в таких случаях: при `-RemoveFiles`; без `-RemoveFiles`/`-KeepFiles`/`-DryRun` — после ответа «да» на вопрос (по умолчанию «нет»).
Удаляются: `agent\`, `dl\`, `agent.log`, `failed_version.txt`, `api_etag.txt`, `api_latest.json`, `repo_root.txt`, `mode.txt`, `host_state.txt`, `sync_last.log`.
`gamma_root.txt` и `installed_version.txt`, а также моды в MO2 НЕ ДОЛЖНЫ трогаться. В тест-режиме и при `-DryRun` задача и ярлык не трогаются
(выводится строка `[DryRun] удалил бы ...`). При `-DryRun` файлы тоже не удаляются.
- Дано: `XRRFIX_HOME=<tmp>\xrrfix` со всеми файлами состояния. Когда: `uninstall_agent.ps1 -RemoveFiles`. Тогда: в `<tmp>\xrrfix` остались только `gamma_root.txt` и `installed_version.txt`.
- Дано: то же. Когда: `-DryRun`. Тогда: ничего не удалено.

## Ошибки и граничные случаи

- **Таймауты**:
  - запрос API — 30 с;
  - скачивание ассета — 300 с;
  - `install.ps1` и `publish.ps1` — по 10 мин (код 124, остановка дерева процессов);
  - `git remote get-url` / `rev-parse` — 60 с (код 124), в setup — 30 с;
  - уведомление держит запуск ~6 с;
  - лимит задачи — 15 мин.
- **Лимит GitHub**: запрос без авторизации, лимит 60 запросов/ч на IP. Агент делает не больше 6 запросов в час (плюс ручные запуски).
  Ответы 304 на условные запросы в лимит не засчитываются.
- **Частично скачанный файл** остаётся как `.part` и удаляется очисткой `dl\` при следующем скачивании.
- **Состояние при ошибке**: при ошибке записи файлов состояния (`api_*`, `repo_root.txt`, `mode.txt`, `host_state.txt`) агент продолжает работу.
  Ошибка записи `failed_version.txt` или `installed_version.txt` приводит к непредвиденной ошибке (код 1).
- **Режим определяется заново каждый запуск**. Клон, появившийся рядом с GAMMA после setup, переключает агент в режим хоста
  без повторного setup. Если клон удалить, агент возвращается в режим пира.
- **`publish.ps1` работает без агента**: в режиме хоста корень GAMMA и профиль он определяет сам (`publish.ini` или родитель клона), см. publish.md.

## Вне области

- Логика инсталлятора (правила секции MO2, маркеры `xrrfix_pack.txt`) — installer.md.
- 3-стороннее сравнение, догон, конфликты, `-TakeRemote`/`-TakeLocal` в `publish.ps1` — publish.md.
- Сборка zip (в том числе папки `agent/` в нём) и выпуск релиза — ci-release.md.
- Проверка целостности модов по хешам из `pack.txt`: агент её не делает.

## Безопасность

- **Права**: всё работает от текущего пользователя без повышения прав. Задача — `RunLevel Limited`, `LogonType Interactive`:
  выполняется только при входе пользователя, пароль не хранится. Setup и uninstall не требуют прав администратора.
- **Что исполняется**:
  - в режиме пира — `install.ps1` из zip, скачанного по `browser_download_url` из ответа API;
  - в режиме хоста — `host\publish.ps1` из рабочей копии клона и `git`;
  - при самообновлении — `.ps1`/`.bat` из zip или из клона.

  Всё это запускается с `-ExecutionPolicy Bypass`. Доверие держится на GitHub-аккаунте и правах записи в репозиторий
  (CI собирает релиз из `main`) и на TLS. Подписи и контрольной суммы архива нет.
- **Переменные `XRRFIX_*`** читаются из окружения пользователя. Тот, кто может их задать, и так выполняет код от имени пользователя.
- **Сеть**: только `api.github.com` (или `XRRFIX_API`), URL ассета из ответа и `git fetch` внутри `publish.ps1`. Авторизация и токены не используются.

## Открытые вопросы / известные ограничения

1. **Лимит задачи меньше худшего случая пира.** Худший запуск пира длится около 15,6 мин: API 30 с + скачивание 300 с + `install.ps1` 600 с + уведомление 6 с.
   Это больше `ExecutionTimeLimit` задачи (15 мин), поэтому Планировщик может остановить агент посреди установки.
   Дочерний `install.ps1`, скорее всего, продолжит работу без контроля таймаута, а результат не запишется в `installed_version.txt`.
2. **Хост: корень GAMMA берётся не из настройки.** `publish.ps1` определяет корень сам (`publish.ini` → `gamma_root`, иначе родитель клона)
   и игнорирует `gamma_root.txt`, выбранный в setup. Если они разойдутся, агент молча синхронизирует другой MO2.
3. **Хост: самообновление из рабочей копии.** Агент обновляется из `<клон>\agent` при любом исходе синхронизации, включая конфликт и ошибку,
   и до того, как `git merge --ff-only` подтянул `origin/main`. Незакоммиченные или неопубликованные правки разработчика сразу попадают
   в работающий агент, а изменения агента с GitHub — только на следующем запуске.
4. **Вывод при таймауте теряется.** Когда дочерний процесс убит по таймауту (код 124), его вывод не сохраняется:
   в `sync_last.log` и `agent.log` остаются только строка с кодом и сообщение о таймауте.
5. **Ключ `noroot` затирает версию.** Неверный корень записывает `noroot` поверх `failed_version.txt` и сбрасывает память о неудачной версии
   (одно уведомление на версию и часовую паузу). Если корень исправлен не через setup, неудача той же версии снова вызовет уведомление.
6. **Общий файл для конфликта и ошибки.** `host_state.txt` хранит один ключ на оба вида уведомлений хоста.
   Если на одном `origin/main` чередуются конфликт и ошибка, уведомления повторяются.
7. **Разный порядок поиска клона.** Setup ищет: родитель папки setup → `repo_root.txt` → папки рядом с GAMMA.
   Агент ищет: `repo_root.txt` → родитель своей папки (это `<home>`, клоном почти никогда не бывает) → папки рядом с GAMMA.
   CONTRACT2 задаёт порядок `repo_root.txt` → папка setup → GAMMA. Кроме того, `XRRFIX_REPO=none` в окружении setup не сохраняется,
   поэтому запуск по расписанию всё равно найдёт клон и включит режим хоста. Постоянно отказаться от режима хоста можно только
   переменной окружения пользователя или удалением клона из видимых мест.
8. **Проверка `origin` по подстроке.** `origin` проверяется по вхождению подстроки, поэтому подходит любой URL с `EduardHavron/xrRazom-GAMMA-fixes`,
   например `.../EduardHavron/xrRazom-GAMMA-fixes-old.git`.
9. **Разные блокирующие процессы у агента и инсталлятора.** По умолчанию инсталлятор блокируется только на `ModOrganizer`, а агент — ещё и на `Anomaly*`.
   Если игра стартовала между проверкой агента и запуском `install.ps1`, установка пойдёт при запущенной игре.
   Сообщение о коде 2 всегда говорит «запущен Mod Organizer».
10. **Тест-режим не изолирован полностью.**
    - `LOCALAPPDATA` подменяется для дочернего процесса, только если `XRRFIX_HOME` оканчивается на `\xrrfix`.
      Иначе `install.ps1` читает и перезаписывает реальный `%LOCALAPPDATA%\xrrfix\gamma_root.txt`, а при неверном пути открывает
      невидимый диалог выбора папки (и висит до таймаута).
    - `setup` в `Find-Root` всегда читает и реальный `%LOCALAPPDATA%\xrrfix\gamma_root.txt`.
11. **`-DryRun` у setup не полностью неинтерактивный.** Без `-GammaRoot` он задаёт вопрос `Это она?` и может открыть диалог выбора папки.
    Кроме того, он вызывает `git` для поиска клона.
12. **TLS не настраивается явно.** Агент не включает TLS 1.2 (`ServicePointManager.SecurityProtocol`).
    На системах со старыми настройками .NET запрос к GitHub будет неудачным с `Нет связи с GitHub (0)`.
13. **Любой 403 считается лимитом.** 403 по другой причине тоже пишется как «лимит запросов».
    `Retry-After` и `X-RateLimit-Reset` не учитываются (при 6 запросах в час это некритично).
14. **Самообновление не атомарно.** Ошибка посреди копирования оставит смесь старых и новых файлов. Удалённые из источника файлы не удаляются.
    Проверяется только синтаксис, ошибки выполнения не ловятся.
15. **Непредвиденные исключения без уведомления.** Пользователь узнает о них только из журнала.
16. **Повторное уведомление при `-Force`.** Переустановка с `-Force` той же версии показывает уведомление «обновлены до <ver>», хотя версия не изменилась.
17. **`Test-Root` и спецсимволы в путях.** `Test-Root` в агенте и setup использует `Test-Path` без `-LiteralPath`, поэтому пути с `[` `]` распознаются неверно.
18. **Uninstall оставляет хвосты.** Он не останавливает уже работающий экземпляр агента и не удаляет саму папку `<home>`.
    В тест-режиме без `-DryRun` он печатает `[DryRun] удалил бы ...`, хотя файлы удаляет по ответу пользователя.
