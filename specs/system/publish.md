# Публикатор: host/publish.ps1
Статус: действует        Код: `host/publish.ps1`, `host/publish.bat`, `host/publish.ini`

## Назначение

Публикует фиксы секции MO2 в `main`, не откатывая чужие изменения. Для каждого мода и для порядка списка сравнивает три
состояния: L (локальный MO2), B (база `merge-base HEAD R`), R (upstream после `git fetch`). Изменения, сделанные только
на GitHub, сначала ставятся в свой MO2 (догон), затем публикуются только локальные изменения. При конфликте ничего не меняет
и завершается с кодом 3. Режим `-SyncOnly` (его использует агент на машине с клоном) выполняет только догон.

## Термины

См. `overview.md`: секция, маркер, L/B/R, база, догон, конфликт, ключ содержимого. Дополнительно:

| Термин | Значение |
|---|---|
| `<absent>` | Состояние мода, которого нет в соответствующем списке (L — не включён в секции; B/R — нет в `pack.json` коммита). |
| Статус мода | `sync` (L=B=R), `equal` (L=R≠B), `remote` (меняется только R), `local` (меняется только L), `conflict`. |
| Итоговое состояние | Состояние мода после синхронизации: R для статуса `remote`, иначе L. |
| Итоговое множество | Моды, чьё итоговое состояние не `<absent>`. |
| Итоговый список | Итоговое множество, упорядоченное правилом PUB-022 (`resList`). |
| Входящие моды | Моды со статусом `remote`, у которых итоговое состояние отличается от L (`incomingMods`). |
| Новый мод | Есть в L, нет ни в списке B, ни в списке R. |

## Входы и выходы

**Параметры**

| Параметр | Тип | Смысл |
|---|---|---|
| `-Message "текст"` | string | Сообщение коммита. `"` заменяются на `'`, пробелы по краям обрезаются. |
| `-NoPrompt` | switch | Никаких вопросов: сообщение коммита — автоматическое, новые моды не публикуются (если нет `-Yes`), ожидание закрытия MO2 — опросом раз в 5 с, слежение за сборкой не предлагается. |
| `-SyncOnly` | switch | Только догон и сдвиг репозитория к R; без коммита и push. |
| `-NoWait` | switch | Если мьютекс занят или нужен догон при запущенных блокирующих процессах — выйти с кодом 2. |
| `-Yes` | switch | Новые моды публиковать без вопроса. |
| `-TakeRemote <имена>` | string[] | Для названных модов взять версию R; `*` — все конфликты и порядок. |
| `-TakeLocal <имена>` | string[] | Для названных модов оставить L (и опубликовать); `*` — все конфликты и порядок. |

Имена в `-Take*`: каждый аргумент сначала сравнивается целиком с известными именами (L ∪ B ∪ R); если не совпал и не `*`,
делится по запятым. Через `powershell -File`/`publish.bat` массив передаётся одной строкой, поэтому несколько модов
указываются через запятую.

**`host/publish.ini`**

Строки `ключ=значение`; строки, начинающиеся с `;` или `#`, — комментарии; ключи без учёта регистра; пробелы вокруг ключа и
значения обрезаются; кавычки не снимаются. Файл читается как UTF-8. Нет файла — все значения по умолчанию.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `gamma_root` | папка над репозиторием | Корень GAMMA (где `ModOrganizer.ini`). Относительный путь — от `host\`. |
| `profile` | `selected_profile` из `ModOrganizer.ini` | Профиль MO2. |
| `section` | `xrRazom Sync` | Имя секции (пустое значение = по умолчанию). |
| `push` | `1` | `0`/`false`/`no`/`нет` (без учёта регистра) — только локальный коммит. |

**Переменные окружения**

| Переменная | Смысл |
|---|---|
| `XRRFIX_BLOCK_PROCS` | Имена процессов через запятую (маски `Get-Process -Name`), при которых догон ждёт/откладывается. По умолчанию `ModOrganizer,Anomaly*`. Передаётся и в дочерний установщик. |

**Машиночитаемый вывод (stdout)**

- `XRRFIX_SYNC_CONFLICT: mods=<имя>[,<имя>…]` — при конфликте; для конфликта порядка добавляется элемент `(порядок модов)`.
- `XRRFIX_SYNC_RESULT: installed=<n> mods=<имя>[,<имя>…]` — после успешного догона; `installed=0 mods=` в `-SyncOnly`, если
  ставить нечего.

**Коды выхода**

| Код | Когда |
|---|---|
| 0 | Успех: опубликовано; «Изменений нет»; `-SyncOnly` завершён; `push=0` (коммит локально); сборка не найдена/не отслеживается. |
| 1 | Ошибка (конфигурация, git, копирование, установщик упал с кодом 1, сборка CI упала при слежении, необработанное исключение). |
| 2 | Отложено: мьютекс занят при `-NoWait`; блокирующие процессы при `-NoWait`; установщик вернул 2. |
| 3 | Конфликт; ничего не изменено. |
| иное | Код установщика при догоне передаётся как есть. |

## Требования

**Конфигурация и предусловия**

### PUB-001 Разрешение корня GAMMA  [auto]
Publish ДОЛЖЕН брать корень GAMMA из `gamma_root` (относительный — от папки `host\`, пустой — родитель папки репозитория),
нормализовать его до полного пути без завершающего `\` и завершаться с кодом 1, если в нём нет `ModOrganizer.ini`.
- Дано `publish.ini` с `gamma_root=..\..\fakeGamma`, где есть `ModOrganizer.ini`. Когда запуск. Тогда используется
  `<repo>\..\fakeGamma` (полный путь).
- Дано `gamma_root` указывает на папку без `ModOrganizer.ini`. Тогда код 1, сообщение «Не найден ModOrganizer.ini … Укажите
  gamma_root», git не вызывается.

### PUB-002 Предусловия репозитория и git  [auto]
Publish ДОЛЖЕН завершаться с кодом 1, если в родителе `host\` нет `.git`, если `git.exe` не найден в PATH, если
`git rev-parse` не работает, или если в репозитории нет коммитов.
- Дано скрипт скопирован в папку без `.git`. Когда запуск. Тогда код 1, «не является git-репозиторием».

### PUB-003 Ключ `push`  [auto]
Значения `push` `0`, `false`, `no`, `нет` (любой регистр) ДОЛЖНЫ отключать `git pull`/`git push`; любое другое значение или
отсутствие ключа — включать.
- Дано `push=No`, локально изменён мод. Когда publish. Тогда коммит создан, `origin/main` не изменился, вывод «push=0 в
  publish.ini …», код 0.

### PUB-004 Единственный экземпляр  [auto]
Publish ДОЛЖЕН захватывать именованный мьютекс `Local\xrrfix_publish` после проверок `ModOrganizer.ini`, `.git` и `git.exe` и до чтения профиля и
остальных вызовов git;
если мьютекс занят: с `-NoWait` — вывести «publish уже выполняется - отложено.» и выйти с кодом 2, без `-NoWait` — ждать его
освобождения без ограничения времени. Брошенный (abandoned) мьютекс ДОЛЖЕН считаться захваченным. Мьютекс ДОЛЖЕН
освобождаться при любом штатном выходе.
- Дано тестовый процесс держит `Local\xrrfix_publish`. Когда `publish.ps1 -SyncOnly -NoWait`. Тогда код 2, `HEAD` и MO2 не
  изменены.
- Дано держатель мьютекса завершился, не освободив его. Когда publish. Тогда publish продолжает работу.

### PUB-005 Выбор профиля  [auto]
Профиль ДОЛЖЕН браться из `profile`, иначе из первой строки `selected_profile=` в `ModOrganizer.ini` с удалением обёртки
`@ByteArray(` … `)`; при отсутствии строки или файла `profiles\<профиль>\modlist.txt` — код 1.
- Дано `selected_profile=@ByteArray(G.A.M.M.A)`. Тогда читается `profiles\G.A.M.M.A\modlist.txt`.

**Секция**

### PUB-006 Поиск разделителя  [auto]
Разделитель ДОЛЖЕН находиться как первая строка `modlist.txt` (UTF-8), у которой текст после первого символа равен
`<section>_separator` (первый символ — любой: `+`, `-`, `*`); если такой строки нет — код 1 с инструкцией создать разделитель.
- Дано в `modlist.txt` нет `xrRazom Sync_separator`. Тогда код 1, сообщение «нет разделителя 'xrRazom Sync'».

### PUB-007 Состав L  [auto]
Список L ДОЛЖЕН состоять из имён строк с префиксом `+`, стоящих выше разделителя до ближайшей вышестоящей строки,
оканчивающейся на `_separator`; строки, начинающиеся с `#`, и строки короче 2 символов пропускаются; строки `-` и `*`
не входят; порядок — как в файле (сверху вниз).
- Дано строки `# header`, `+X`, `+Other_separator`, `+B`, `-C`, `*D`, `+A`, `+xrRazom Sync_separator`, `+Y`. Тогда L = `[B, A]`.

### PUB-008 Проверка L  [auto]
Если L пуст — код 1 («нет включённых модов»); если для какого-то имени из L нет папки `<gamma_root>\mods\<имя>` — код 1
со списком всех отсутствующих.
- Дано `+A` в секции, папки `mods\A` нет. Тогда код 1, в сообщении `  - A`.

**Git: безопасность и состояние**

### PUB-009 Незавершённые операции git  [auto]
Если в каталоге git есть `rebase-merge`, `rebase-apply`, `MERGE_HEAD`, `CHERRY_PICK_HEAD` или `REVERT_HEAD`, publish ДОЛЖЕН
завершиться с кодом 1, ничего не меняя.
- Дано в клоне начат `git rebase` с конфликтом. Когда publish. Тогда код 1, «не завершён rebase/merge».

### PUB-010 Сброс остатков в `mods/` и `pack/`  [auto]
Перед сравнением publish ДОЛЖЕН отменить все незакоммиченные изменения в `mods/` и `pack/` рабочего дерева (индекс,
отслеживаемые и неотслеживаемые файлы) и сообщить об этом; изменения вне этих папок НЕ ДОЛЖНЫ затрагиваться.
- Дано изменён `mods/A/x`, создан `mods/Z/y`, изменён `README.md`. Когда publish. Тогда `mods/A/x` = `HEAD`, `mods/Z` нет,
  `README.md` по-прежнему изменён.

### PUB-011 Fetch и определение R  [auto]
Publish ДОЛЖЕН выполнить `git fetch`; при ошибке — код 1. R ДОЛЖЕН быть коммитом upstream текущей ветки (`@{u}`), а если
upstream не настроен — `origin/main`; если и он не разрешается, R = `HEAD`.
- Дано origin недоступен. Тогда код 1, «git fetch не удался».

### PUB-012 База  [auto]
B ДОЛЖНА быть `git merge-base HEAD R`; если общей истории нет — код 1. Признак «R впереди» — R не является предком `HEAD`.
- Дано локальный `HEAD` = X, друг запушил Y поверх X. Тогда B = X, R = Y, R впереди.
- Дано локальный неотправленный коммит Z поверх X, R = Y поверх X. Тогда B = X.

### PUB-013 Защита незакоммиченных файлов вне `mods/`, `pack/`  [auto]
Если R впереди, publish ДОЛЖЕН завершиться с кодом 1 до любых изменений, когда отслеживаемый файл вне `mods/`, `pack/`
изменён в рабочем дереве или индексе и одновременно отличается между `HEAD` и R; сообщение ДОЛЖНО перечислять такие файлы
и советовать `git stash`.
- Дано локально изменён `host/publish.ini`, на GitHub тоже изменён `host/publish.ini`. Тогда код 1, в списке
  `host/publish.ini`, MO2 не изменён.
- Дано локально изменён `host/publish.ini`, на GitHub он не менялся. Тогда проверка проходит.

**Сравнение**

### PUB-014 Ключ содержимого  [auto]
Содержимое мода ДОЛЖНО сравниваться по ключу: отсортированные (ординально) строки `<путь с />\t<git blob id>` всех файлов
мода (рекурсивно, включая скрытые), кроме верхнеуровневых `meta.ini` и `xrrfix_pack.txt`. Для L blob id ДОЛЖЕН вычисляться
по сырым байтам файла (SHA-1 от `blob <размер>\0<байты>`, что равно `git hash-object --no-filters`); для B и R — из
`git ls-tree -r <коммит> -- mods`.
- Дано файл с CRLF, идентичный по байтам файлу в R. Тогда ключи L и R равны.
- Дано отличие в один байт в `gamedata/x.script`. Тогда ключи различны.
- Дано отличаются только `meta.ini` или маркер. Тогда ключи равны.

### PUB-015 Состояние мода в стороне  [auto]
Состояние мода в стороне X ДОЛЖНО быть `<absent>`, если имени нет в списке X (L — включённые моды секции; B, R — `mods`
из `pack.json` соответствующего коммита), иначе — ключом содержимого (пустая строка, если файлов нет). Папки
`mods/<имя>` коммита, отсутствующие в его `pack.json`, ДОЛЖНЫ считаться `<absent>`. Если `pack.json` в коммите нет,
список пуст.
- Дано в R есть `mods/C/…`, но C нет в `pack.json` R. Тогда R(C) = `<absent>`.

### PUB-016 Таблица L/B/R для мода  [auto]
Для каждого имени из объединения L ∪ R ∪ B статус ДОЛЖЕН определяться так (сравнение строк с учётом регистра):

| Условие | Статус | Итоговое состояние |
|---|---|---|
| L = R, L = B | `sync` | L |
| L = R, L ≠ B | `equal` | L |
| L ≠ R, L = B | `remote` | R |
| L ≠ R, R = B | `local` | L |
| L ≠ R, L ≠ B, R ≠ B | `conflict` | L |

- Дано A: L=B=k1, R=k2. Тогда `remote`. Дано A: L=k2, B=R=k1. Тогда `local`. Дано A: L=R=k2, B=k1. Тогда `equal`.
- Дано A: B=k1, L=k2, R=`<absent>` (удалён на GitHub, изменён локально). Тогда `conflict`.
- Дано A только в L. Тогда `local` (и A — новый мод).
- Дано A только в B (убран и локально, и на GitHub). Тогда `equal`, A не входит в итоговое множество.

### PUB-017 Выбор стороны `-TakeRemote` / `-TakeLocal`  [auto]
Для мода, названного в `-TakeRemote`, со статусом `remote`, `local` или `conflict` статус ДОЛЖЕН становиться `remote`;
иначе для мода, названного в `-TakeLocal`, — `local`. `*` ДОЛЖЕН действовать только на моды со статусом `conflict`
(и на порядок, PUB-019). Статусы `sync`/`equal` НЕ ДОЛЖНЫ меняться. Если мод назван в обоих — побеждает `-TakeRemote`.
Неизвестное имя ДОЛЖНО пропускаться с предупреждением «мод '…' не найден ни локально, ни в репозитории».
- Дано A в `conflict`. Когда `-TakeRemote "A"`. Тогда A ставится из R, конфликта нет.
- Дано A в `local` (не конфликт). Когда `-TakeRemote "A"`. Тогда локальные правки A заменяются версией R при догоне.
- Дано A и B в `conflict`. Когда `-TakeLocal "A,B"`. Тогда оба `local`.
- Дано A в `local`, B в `conflict`. Когда `-TakeRemote "*"`. Тогда A остаётся `local`, B → `remote`.

### PUB-018 Новые моды  [auto]
Мод ДОЛЖЕН считаться новым, если он есть в L и отсутствует в списках B и R.
- Дано D включён в секции, его нет в `pack.json` ни B, ни R. Тогда D — новый (в отчёте `[>] D - новый мод`).

### PUB-019 Порядок списка и конфликт порядка  [auto]
Порядок ДОЛЖЕН считаться изменённым локально, если общие для L и B моды идут в L в другом относительном порядке, чем в B;
аналогично для R. Конфликт порядка ДОЛЖЕН фиксироваться, если порядок изменён с обеих сторон и общие для L и R моды идут
в разном относительном порядке. `-TakeRemote *` ДОЛЖЕН отбрасывать локальное изменение порядка, `-TakeLocal *` (если
`-TakeRemote *` не задан) — удалённое. Добавления и удаления модов изменением порядка не считаются.
- Дано B=[A,C], L=[C,A], R=[A,C]. Тогда изменён только локально, конфликта нет.
- Дано B=[A,C,E], L=[C,A,E], R=[A,E,C]. Тогда конфликт порядка (код 3, `(порядок модов)` в списке конфликтов).
- Дано тот же случай и `-TakeLocal "*"`. Тогда итоговый порядок [C,A,E].

### PUB-020 Итоговый список  [auto]
Итоговый список ДОЛЖЕН содержать ровно итоговое множество; за основу ДОЛЖЕН браться L, если порядок изменён локально,
иначе R; из основы берутся имена итогового множества в её порядке, затем имена из другой стороны, которых нет в основе,
вставляются по порядку другой стороны сразу после ближайшего предшествующего (в другой стороне) имени, уже стоящего в
результате, а если такого нет — в начало.
- Дано L=[A,D,B] (D новый), R=[A,B], порядок не менялся. Тогда итог [A,D,B].
- Дано L=[A,B], R=[N,A,B] (N добавлен на GitHub). Тогда итог [N,A,B].
- Дано B=[A,B], L=[B,A] (локальная перестановка), R=[A,B,N]. Тогда итог [B,N,A] (N встаёт сразу после B — своего
  предшественника в R).

**Отчёт и конфликт**

### PUB-021 Отчёт сравнения  [auto]
Publish ДОЛЖЕН печатать заголовок `Сравнение с GitHub (<upstream> <sha7 R>):` и по строке на мод: `[<]` для входящих
(«изменён на GitHub, будет установлен» / «удалён на GitHub, будет выключен»), `[>]` для `local` («новый мод» / «убран
локально» / «изменён локально»), `[!]` для `conflict`; `[!] порядок модов изменён и локально, и на GitHub` для конфликта
порядка; `[<] порядок модов (с GitHub)`, если меняется только порядок; иначе «всё совпадает».
- Дано всё в `sync`. Тогда в выводе `  всё совпадает`.

### PUB-022 Остановка при конфликте  [auto]
Если есть хотя бы один мод со статусом `conflict` или конфликт порядка, publish ДОЛЖЕН вывести список конфликтов,
подсказки (`publish.bat -SyncOnly -TakeRemote "<мод>"` и `publish.bat -TakeLocal "<мод>"`, где `<мод>` — первый
конфликтующий мод или `*`, если конфликтует только порядок), строку `XRRFIX_SYNC_CONFLICT: mods=<имена через запятую>`
и завершиться с кодом 3, НЕ меняя MO2, `HEAD` и `origin`; это ДОЛЖНО происходить и в режиме `-SyncOnly`.
- Дано A и B в конфликте. Тогда код 3, строка `XRRFIX_SYNC_CONFLICT: mods=A,B`, `modlist.txt` и папки модов не изменены,
  `HEAD` не сдвинут, временной папки нет.
- Дано только конфликт порядка. Тогда строка `XRRFIX_SYNC_CONFLICT: mods=(порядок модов)`.

**Догон**

### PUB-023 Когда нужен догон  [auto]
Догон ДОЛЖЕН выполняться тогда и только тогда, когда есть входящие моды или (нет конфликта порядка и) итоговый список
отличается от L.
- Дано изменения на GitHub только в `installer/` или `README.md`. Тогда догона нет, установщик не запускается.
- Дано на GitHub изменён только порядок. Тогда догон есть, `XRRFIX_SYNC_RESULT: installed=0 mods=`.

### PUB-024 Блокирующие процессы  [auto]
Перед догоном publish ДОЛЖЕН проверить процессы из `XRRFIX_BLOCK_PROCS` (по умолчанию `ModOrganizer`, `Anomaly*`): если
найдены — с `-NoWait` вывести сообщение об отложенной установке и выйти с кодом 2; с `-NoPrompt` (без `-NoWait`) —
опрашивать раз в 5 секунд до их закрытия; иначе — просить закрыть MO2 и нажать Enter, повторяя, пока процессы есть.
Если догон не нужен, запущенные процессы НЕ ДОЛЖНЫ мешать (публикация не трогает MO2).
- Дано `XRRFIX_BLOCK_PROCS=FakeMO`, запущен `FakeMO.exe`, на GitHub изменён A. Когда `-SyncOnly -NoWait`. Тогда код 2,
  MO2 и `HEAD` не изменены.
- Дано тот же процесс запущен, догон не нужен, локально изменён D. Когда publish. Тогда D опубликован, код 0.

### PUB-025 Состав временного пакета  [auto]
Publish ДОЛЖЕН собрать временный пакет в `%TEMP%\xrrfix_sync_<8 hex>\` с `mods\<имя>` для каждого имени итогового списка:
для модов, чьё итоговое состояние отличается от L, — содержимое `mods/<имя>` из R (через `git archive R -- mods`), плюс
локальный `meta.ini`, если он есть; если в R у мода нет файлов — пустую папку; для остальных — копию локальной папки
(`robocopy /E /COPY:DAT`; код robocopy ≥ 8 → код 1).
- Дано A входящий, D `local`. Тогда во временном пакете `mods\A` = R + локальный `meta.ini`, `mods\D` = локальная папка
  (с неопубликованными правками).

### PUB-026 `pack.txt` временного пакета  [auto]
Временный `pack.txt` ДОЛЖЕН быть UTF-8 без BOM с LF: `version=sync-<sha7 R>`, `profile=github`, `section=<секция>`,
пустая строка и строки `[mod] <имя>` в порядке итогового списка, без строк хэшей; рядом ДОЛЖНА лежать копия
`installer\install.ps1` из рабочего дерева репозитория.
- Дано R=`abc1234…`, итог [A,D]. Тогда `pack.txt` = `version=sync-abc1234\nprofile=github\nsection=xrRazom Sync\n\n[mod] A\n[mod] D\n`.

### PUB-027 Выключение убранных модов  [auto]
Для каждого мода из L, не попавшего в итоговый список, publish ДОЛЖЕН до запуска установщика записать в его локальную папку
маркер `xrrfix_pack.txt` (`xrRazom fixes pack sync-<sha7>`), чтобы установщик выключил его в секции; папка мода НЕ ДОЛЖНА
удаляться.
- Дано друг убрал A из `pack.json`, у хоста A не менялся. Когда догон. Тогда в `modlist.txt` хоста строка `-A` осталась в секции,
  `mods\A` существует и содержит маркер.

### PUB-028 Вызов установщика  [auto]
Publish ДОЛЖЕН запустить дочерний `powershell.exe -NoProfile -ExecutionPolicy Bypass -NonInteractive` с
`install.ps1 -NoWait -GammaRoot <gamma_root> -Profile <профиль>` из временного пакета, печатая его вывод с отступом в 2
пробела; при ненулевом коде установщика — завершиться с тем же кодом (2 → «Установка отложена», иное — «ОШИБКА: установка …
не удалась»).
- Дано установщик вернул 2 (MO2 запустили между проверками). Тогда publish выходит с кодом 2, `HEAD` не сдвинут.

### PUB-029 Строка результата догона  [auto]
После успешной установки publish ДОЛЖЕН удалить временную папку и вывести `XRRFIX_SYNC_RESULT: installed=<число входящих
модов> mods=<входящие через запятую>` (в любом режиме); в режиме `-SyncOnly` без догона — `XRRFIX_SYNC_RESULT: installed=0 mods=`;
в обычном режиме без догона строка НЕ выводится.
- Дано входящие A и B. Тогда `XRRFIX_SYNC_RESULT: installed=2 mods=A,B`.

### PUB-030 Порядок: сначала MO2, потом репозиторий  [auto]
Сдвиг `HEAD` к R ДОЛЖЕН выполняться только после успешной установки (или если установка не нужна). Если установка отложена
или упала, `HEAD` НЕ ДОЛЖЕН сдвигаться, чтобы B не изменилась и следующий запуск снова увидел входящие изменения (иначе
они выглядели бы как локальные и были бы откачены публикацией).
- Дано на GitHub изменён A, установщик падает. Когда publish. Тогда код ≠ 0, `HEAD` прежний; при следующем успешном запуске
  A по-прежнему `remote` и ставится.

### PUB-031 Сдвиг репозитория к R  [auto]
Если R впереди: при `HEAD`-предке R ДОЛЖЕН выполняться `git merge --ff-only R` (ошибка: в `-SyncOnly` — предупреждение и
продолжение, иначе код 1); при расхождении (есть неотправленные локальные коммиты) вне `-SyncOnly` — `git rebase --autostash R`
(ошибка: `git rebase --abort` и код 1); в `-SyncOnly` при расхождении `HEAD` НЕ ДОЛЖЕН меняться. Шаг выполняется и тогда,
когда догон не нужен.
- Дано друг изменил только `README.md`. Когда `-SyncOnly`. Тогда `HEAD` = R, код 0.
- Дано неотправленный локальный коммит и новый коммит на GitHub. Когда `-SyncOnly`. Тогда `HEAD` не изменён.

### PUB-032 Завершение `-SyncOnly`  [auto]
В режиме `-SyncOnly` после PUB-031 publish ДОЛЖЕН завершиться с кодом 0, НЕ создавая коммитов и не выполняя push; при
наличии модов `local` ДОЛЖЕН вывести «Неопубликованные локальные изменения: <имена> (запустите publish.bat)».
- Дано локально изменён D. Когда `-SyncOnly`. Тогда код 0, коммитов нет, в выводе D.

**Публикация**

### PUB-033 Подтверждение новых модов  [auto]
Для каждого нового мода со статусом `local`: с `-Yes` — публиковать; иначе с `-NoPrompt` — не публиковать и сообщить
«не публикуется (новый, не подтверждён)»; иначе спросить `(y/N)` (подтверждение — `y`, `yes`, `д`, `да`). Неподтверждённый
мод НЕ ДОЛЖЕН попадать в `mods/` и `pack.json`, но остаётся в MO2 и при следующем запуске снова считается новым.
Перед сравнением ответ ДОЛЖЕН очищаться от любых не-буквенных символов в начале (`-replace '^[^\p{L}]+'`) и пробелов по краям:
при перенаправленном вводе в начале может прийти BOM, прочитанный в кодовой странице консоли (например `∩╗┐` в OEM 437).
- Дано новый D, ответ из stdin `<EF BB BF>y`. Тогда D публикуется (так выглядел ввод на GitHub windows-раннере).
- Дано новый D. Когда `-NoPrompt` без `-Yes`. Тогда D нет в коммите и в `pack.json`, вывод содержит предупреждение.
- Дано новый D. Когда `-NoPrompt -Yes`. Тогда D в коммите и в `pack.json`.

### PUB-034 Зеркалирование только локальных изменений  [auto]
В `mods/` репозитория ДОЛЖНЫ переписываться только моды со статусом `local` (кроме неподтверждённых новых): папка удаляется
и, если итоговое состояние не `<absent>`, копируется из MO2 (`robocopy /E /COPY:DAT`) с удалением верхнеуровневых `meta.ini` и
`xrrfix_pack.txt`. Моды с остальными статусами НЕ ДОЛЖНЫ перезаписываться (их содержимое в рабочем дереве = R после PUB-031).
- Дано A `remote`, D `local`. Тогда в коммите изменён только `mods/D/**`, `mods/A` = R.
- Дано D выключен локально (был в B и R). Тогда `mods/D` удалён в коммите, D нет в `pack.json`.

### PUB-035 Запись списка  [auto]
Список для `pack.json` ДОЛЖЕН быть итоговым списком без неподтверждённых новых модов; файл ДОЛЖЕН записываться по правилам
REPO-005 (только если список или секция отличаются от `pack.json` в `HEAD`; секция = значение `section` из конфигурации).
- Дано на GitHub порядок [A,B], локально [B,A] (только локальная перестановка). Тогда коммит меняет только `pack/pack.json`,
  отчёт `[*] порядок модов (pack.json)`, сообщение по умолчанию `Update fixes: mod order`.

### PUB-036 Коммит  [auto]
Publish ДОЛЖЕН выполнить `git add -A -- mods pack` и, если есть изменения, коммит только путей `mods` и `pack`; вывести сводку
`[+]` (нет в `HEAD`), `[-]` (удалён), `[*]` (изменён) по папкам модов; сообщение — `-Message`, иначе (без `-NoPrompt`) ввод
пользователя, иначе `Update fixes: <имена через ", ">` или `Update fixes: mod order`; `"` в сообщении заменяются на `'`.
Введённое описание ДОЛЖНО очищаться от символа `U+FEFF` в начале и пробелов по краям.
- Дано изменён D, `-NoPrompt`. Тогда сообщение коммита `Update fixes: D`.
- Дано `-Message 'Fix "x"'`. Тогда сообщение `Fix 'x'`.

### PUB-037 Нет изменений и досылка неотправленных коммитов  [auto]
Если после `git add` индекс по `mods`/`pack` не отличается от `HEAD`: при `push` включённом и числе коммитов `@{u}..HEAD` > 0
publish ДОЛЖЕН сообщить «Новых изменений нет, но N коммит(ов) ещё не отправлено» и перейти к pull/push; иначе — вывести
«Изменений нет» и завершиться с кодом 0.
- Дано прошлый push упал, коммит остался локально, MO2 не менялся. Когда publish. Тогда коммит отправлен, код 0.
- Дано всё синхронно. Тогда «Изменений нет», код 0, `git push` не вызывается.

### PUB-038 `push=0`  [auto]
При выключенном `push` publish ДОЛЖЕН после коммита вывести «коммит создан локально, отправка пропущена» и выйти с кодом 0,
не вызывая `git pull` и `git push`.
- См. PUB-003.

### PUB-039 Отправка  [auto]
Publish ДОЛЖЕН выполнить `git pull --rebase --autostash`, затем `git push`; при ошибке любого шага — код 1 с сообщением,
что коммит остался локально (для pull) или о проверке доступа (для push).
- Дано между fetch и push друг запушил изменение другого мода. Когда publish. Тогда pull --rebase переносит коммит поверх,
  push успешен, код 0.
- Дано удалённый репозиторий отвергает push. Тогда код 1, коммит есть локально, при следующем запуске он досылается (PUB-037).

### PUB-040 Поиск запуска GitHub Actions  [manual]
После успешного push publish ДОЛЖЕН: взять URL Actions из `origin` (иначе запасной URL репозитория); если `gh` не найден
(PATH или `C:\Program Files\GitHub CLI\gh.exe`) или origin не на github.com — вывести URL и выйти с кодом 0; иначе до 10 раз
с паузой 3 с искать среди `gh run list --limit 5` запуск с `headSha` = `HEAD`; не найден — сообщение и код 0; найден — вывести
URL и статус; с `-NoPrompt` — код 0; иначе спросить «Следить за сборкой? (y/N)» (ответ очищается как в PUB-033), при согласии `gh run watch --exit-status`:
неуспех — код 1, успех — вывести URL релиза и код 0.
- Дано `gh` нет в PATH. Тогда вывод `Сборка релиза: https://github.com/<owner>/<repo>/actions`, код 0.

## Ошибки и граничные случаи

- Удалённый мод (R = `<absent>`) с неизменённым L: статус `remote`, догон выключает его через маркер; локальная папка остаётся.
- Мод выключен локально временно (для теста): он выпадает из L и публикуется как удаление (`[>] … - убран локально`).
- Неотправленные локальные коммиты: B = merge-base, их содержимое не участвует в сравнении; если L совпадает с ними,
  публикация даёт пустой индекс и они досылаются (PUB-037).
- Необработанное исключение (например, повреждённый `pack.json` в B/R → `ConvertFrom-Json`) завершает процесс с кодом 1
  без `Quit`: временная папка может остаться.
- Пустой итоговый список (все моды неподтверждённые новые или всё удалено на GitHub) приведёт к `pack.json` с пустым `mods`,
  который CI отвергнет.

## Открытые вопросы / известные ограничения

1. **B — merge-base, а не `HEAD`.** CONTRACT2: «B = repo `HEAD` version». Код использует `git merge-base HEAD R`; при
   неотправленных локальных коммитах это разные коммиты. Код главнее; спецификация следует коду.
2. **Порядок догона и fast-forward.** CONTRACT2 (шаг 5): сначала fast-forward/rebase, потом временный пакет и установщик.
   Код ставит в MO2 **до** сдвига `HEAD` (PUB-030) — это безопаснее: при упавшей/отложенной установке база не сдвигается.
   Следствие: во временный пакет кладётся `install.ps1` из **текущего** (старого) рабочего дерева, а не из R.
3. **Итоговый список.** CONTRACT2: «resulting list = Llist if the list is LOCAL-ONLY changed, else Rlist». Код строит
   членство из по-модовых итогов и порядок слиянием (PUB-020); конфликт порядка определяется по относительному порядку общих
   модов, а не «таблицей для списка целиком».
4. **`-TakeLocal`** в CONTRACT2 отсутствует (есть только `-TakeRemote`); в коде есть. Подсказка в CONTRACT2 «или просто
   переопубликуйте после правки» в коде заменена на `-TakeLocal`.
5. **`-TakeRemote`/`-TakeLocal` по имени действуют не только на конфликты** (меняют и статусы `local`/`remote`), а `*` —
   только на конфликты; при этом `-TakeRemote *` молча отбрасывает и неконфликтную локальную перестановку порядка
   (PUB-019), а `-TakeLocal *` — неконфликтную удалённую. Асимметрично с поведением `*` для модов.
6. **Подсказка при смешанном конфликте.** Если есть и конфликт модов, и конфликт порядка, подсказка предлагает
   `-TakeRemote "<первый мод>"`, что не снимает конфликт порядка (нужен `*`); снимается только повторным запуском с `*`.
7. **Проверка грязных файлов** (PUB-013) учитывает только отслеживаемые файлы: неотслеживаемый файл, который добавляет R,
   приведёт к ошибке `merge --ff-only` уже **после** установки в MO2 (в `-SyncOnly` — лишь предупреждение, код 0). Разбор
   `status --porcelain -z` берёт `Substring(3)` и для записей переименования (отдельное поле исходного пути) даёт неверный путь.
8. **Ожидание без таймаута.** `-NoPrompt` без `-NoWait` при запущенном MO2 опрашивает бесконечно; мьютекс без `-NoWait`
   ждётся бесконечно.
9. **Гонка fetch → push.** Защита от отката действует на момент `fetch`. Если другой человек запушит между fetch и push,
   `pull --rebase` сливает построчно: изменение того же мода в разных файлах сольётся без 3-стороннего анализа на уровне мода;
   `pack.json` почти всегда даёт конфликт rebase → код 1 (коммит остаётся локально).
10. **Имя секции не участвует в 3-стороннем сравнении.** Если на GitHub `pack.json.section` переименована, а в локальном
    `publish.ini` старое имя, публикация перезапишет `section` своим значением (откат).
11. **Маркеры у публикующего.** Установщик пишет маркер во все моды пакета, включая локальные копии; после первого догона все
    моды секции у публикующего — «наши». Если затем вынести такой мод из секции вручную, следующий догон выключит его вне секции
    (правило установщика). Выключенные моды секции без маркера при догоне переносятся установщиком под разделитель (из секции).
12. **Проверка корня.** Publish требует `ModOrganizer.ini`, а установщик с `-GammaRoot` — `ModOrganizer.exe` и `mods\`; корень
    без `ModOrganizer.exe` проходит проверку publish, но догон падает с кодом 1.
13. **Разделитель в `XRRFIX_SYNC_*`** — запятая; имена модов с запятыми разбираются неоднозначно (агент тоже делит по запятым).
14. **Регистр имён.** `-contains`/хеш-таблицы PowerShell нечувствительны к регистру, `List.Contains` и `-ceq` — чувствительны;
    переименование мода только регистром даёт неопределённый результат.
15. **Без upstream** (`@{u}` не настроен) R берётся из `origin/main`, но `git pull`/`git push` без upstream упадут (код 1), а
    досылка неотправленных коммитов (PUB-037) их не увидит.
16. **`gh release view`** без тега показывает последний релиз, который может быть не тем, что собрал отслеживаемый запуск.
17. **Конфликт и сброс остатков.** Сообщение «Ничего не изменено» при коде 3 верно для MO2 и `HEAD`, но PUB-010 к этому моменту
    уже сбросил незакоммиченные изменения в `mods/`, `pack/`.
