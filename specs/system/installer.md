# Установщик пакета у получателя
Статус: действует        Код: `installer/install.ps1`, `installer/install.bat`, `installer/README.txt`

## Назначение
Ставит моды пакета (распакованный `xrRazom_fixes.zip` или временный пакет `publish.ps1 -SyncOnly`) в GAMMA (Mod Organizer 2)
и пересобирает в профиле MO2 **только** секцию пакета (по умолчанию «xrRazom Sync»), чтобы набор и порядок фиксов совпадал с хостом
байт-в-байт (иначе xrRazom не пустит в игру). Чужие и тестовые моды получателя не удаляются и не выключаются.
Вызывается вручную (`install.bat`), агентом пира (`install.ps1 -NoWait`) и `publish.ps1` (`-NoWait -GammaRoot … -Profile …`).

## Термины
- **Пакет** — папка, где лежит `install.ps1` (`$PSScriptRoot`): `pack.txt`, `mods/<имя>/…`.
- **Корень GAMMA** — папка, где есть файл `ModOrganizer.exe` и папка `mods`.
- **Секция** — значение `section=` из pack.txt (по умолчанию `xrRazom Sync`); **разделитель** — мод `<section>_separator`.
- **Строки секции** — строки modlist.txt над строкой разделителя до ближайшей выше строки, начинающейся с `#` или оканчивающейся на `_separator` (не включая её).
- **Маркер** — файл `xrrfix_pack.txt` в корне папки мода; признак «мод поставлен этим установщиком».
- **Наш мод** — мод из `$LEGACY` (`zz xrRazom Fixes`) или мод, у которого в `<root>\mods\<имя>\` есть маркер.
- **Чужой мод** — любой другой мод.
- **Моды пакета** — имена из строк `[mod] ` pack.txt в их порядке.

## Входы и выходы
| Вход | Описание |
|---|---|
| `-NoWait` | не ждать закрытия блокирующих процессов, а выйти с кодом 2 |
| `-GammaRoot <путь>` | корень GAMMA без поиска; сохранённый путь не меняется |
| `-Profile <имя>` (параметр `ProfileName`, алиас `Profile`) | профиль MO2 вместо `selected_profile` |
| `XRRFIX_BLOCK_PROCS` (env) | имена процессов через запятую; по умолчанию `ModOrganizer` |
| `%LOCALAPPDATA%\xrrfix\gamma_root.txt` | сохранённый корень GAMMA (первая строка), общий с агентом |
| `<пакет>\pack.txt`, `<пакет>\mods\` | содержимое пакета |
| `<root>\ModOrganizer.ini` | строка `selected_profile=@ByteArray(<имя>)` |
| `<root>\profiles\<профиль>\modlist.txt` | список модов MO2 (первая строка — высший приоритет) |

| Выход | Описание |
|---|---|
| `<root>\mods\<имя>\` | копия мода пакета + маркер |
| `<root>\mods\<section>_separator\meta.ini` | создаётся, если папки разделителя нет |
| `modlist.txt` | пересобранный список (UTF-8 без BOM, CRLF) |
| `modlist.txt.xrrfix.bak` | копия modlist.txt до изменения |
| `gamma_root.txt` | найденный корень (только без `-GammaRoot`) |

| Код выхода | Когда |
|---|---|
| 0 | установка завершена (в т.ч. когда modlist.txt не найден — INS-024) |
| 1 | любая ошибка (`$ErrorActionPreference = 'Stop'`, необработанное исключение) |
| 2 | `-NoWait` и запущен блокирующий процесс; моды и modlist не тронуты |

## Требования

### INS-001 Запуск через install.bat  [manual]
`install.bat` ДОЛЖЕН запускать `powershell -NoProfile -ExecutionPolicy Bypass -File "<папка bat>\install.ps1"` без аргументов и затем `pause`, чтобы окно не закрылось.
- Дано распакованный архив. Когда пользователь запускает `install.bat` двойным щелчком. Тогда выполняется `install.ps1` из той же папки, после завершения окно ждёт нажатия клавиши.

### INS-002 Кодировка скриптов  [auto]
`install.ps1` ДОЛЖЕН храниться в UTF-8 с BOM (содержит кириллицу; Windows PowerShell 5.1), `install.bat` — в ASCII с CRLF; синтаксис — только Windows PowerShell 5.1 (без `??`, `?.`, тернарного оператора, `&&`).
- Дано файл `installer/install.ps1`. Когда читаются первые 3 байта. Тогда это `EF BB BF`.

### INS-003 Явный корень GAMMA  [auto]
При заданном `-GammaRoot` установщик ДОЛЖЕН взять `[IO.Path]::GetFullPath(<значение>)` без конечных `\`, НЕ ДОЛЖЕН выполнять поиск и НЕ ДОЛЖЕН изменять `gamma_root.txt`; если в папке нет `ModOrganizer.exe` или `mods`, ДОЛЖЕН завершиться с ошибкой «В '<root>' нет ModOrganizer.exe и папки mods» (код 1) до каких-либо изменений.
- Дано `gamma_root.txt` = `D:\A`, вызов `-GammaRoot D:\B\` (корректный корень). Когда установка завершена. Тогда изменён `D:\B`, `gamma_root.txt` по-прежнему `D:\A`.
- Дано `-GammaRoot D:\Empty`. Тогда код 1, никаких файлов не изменено.

### INS-004 Поиск корня GAMMA  [auto]
Без `-GammaRoot` установщик ДОЛЖЕН искать корень в порядке, возвращая первый подходящий:
1. первая строка `%LOCALAPPDATA%\xrrfix\gamma_root.txt` (обрезанная по пробелам), если файл есть и путь — корень GAMMA;
2. папка пакета и все её родители вверх до корня диска;
3. для каждого диска файловой системы (в порядке `Get-PSDrive`) подпапки `GAMMA`, `G.A.M.M.A`, `Gamma`, `Games\GAMMA`, `Games\Gamma`, `Games\G.A.M.M.A`, `Stalker\GAMMA` (в этом порядке);
4. диалог выбора папки (`FolderBrowserDialog`, «Выберите папку GAMMA (где лежит ModOrganizer.exe)»), повторяемый с сообщением «В этой папке нет ModOrganizer.exe и папки mods.», пока выбрана неподходящая папка; отмена диалога — ошибка «Папка GAMMA не выбрана» (код 1).
- Дано сохранённый путь указывает на удалённую папку, пакет распакован в `D:\Games\Gamma\tmp\pkg`, `D:\Games\Gamma` — корень. Когда установка. Тогда корень = `D:\Games\Gamma`.
- Дано сохранённого пути нет, `E:\GAMMA` — корень. Тогда корень = `E:\GAMMA` без диалога.

### INS-005 Сохранение найденного корня  [auto]
Без `-GammaRoot` найденный корень ДОЛЖЕН записываться в `%LOCALAPPDATA%\xrrfix\gamma_root.txt` (папка создаётся при необходимости) до проверки блокирующих процессов; в консоль ДОЛЖНА выводиться строка `GAMMA: <root>`.
- Дано корень найден по п.2 INS-004. Когда установка (даже завершившаяся кодом 2). Тогда `gamma_root.txt` содержит этот путь.

### INS-006 Список блокирующих процессов  [auto]
Блокирующими ДОЛЖНЫ считаться процессы с именами из `XRRFIX_BLOCK_PROCS` (разбиение по `,`, обрезка пробелов, пустые элементы отбрасываются) если переменная непуста, иначе `ModOrganizer`; совпадение — по `Get-Process -Name` (без учёта регистра, допускаются шаблоны `*`).
- Дано `XRRFIX_BLOCK_PROCS=" foo , ,Anomaly*"`. Тогда блокируют `foo` и `Anomaly*`, `ModOrganizer` — нет.
- Дано `XRRFIX_BLOCK_PROCS=","`. Тогда блокирующих процессов нет (используется в тестах).

### INS-007 Отложенная установка с -NoWait  [auto]
При `-NoWait` и запущенном блокирующем процессе установщик ДОЛЖЕН вывести «Mod Organizer запущен - установка отложена.» и завершиться с кодом 2, НЕ изменяя моды, разделитель, modlist.txt и бэкап.
- Дано запущен процесс из списка, `-NoWait`. Когда установка. Тогда код 2, `<root>\mods` и `modlist.txt` побайтно без изменений.

### INS-008 Ожидание закрытия MO2  [manual]
Без `-NoWait` при запущенном блокирующем процессе установщик ДОЛЖЕН в цикле выводить «Закройте Mod Organizer (и игру), затем нажмите Enter...» и ждать Enter, пока блокирующие процессы есть; после их закрытия — продолжать установку.

### INS-009 Чтение pack.txt  [auto]
Установщик ДОЛЖЕН читать `<пакет>\pack.txt` как UTF-8 и брать: версию из строки `version=…`, секцию из `section=…` (пустая/отсутствует → `xrRazom Sync`), моды пакета — из строк, начинающихся с `[mod] ` (имя = текст после первых 6 символов, без обрезки), в порядке файла. Прочие строки (`profile=`, строки хешей) ДОЛЖНЫ игнорироваться. Отсутствие pack.txt — ошибка (код 1) до изменения модов.
- Дано pack.txt из CI-017 с `section=Test`. Тогда разделитель — `Test_separator`, моды — по строкам `[mod] `.

### INS-010 Пакет без строк [mod]  [auto]
Если в pack.txt нет ни одной строки `[mod] `, моды пакета ДОЛЖНЫ браться из имён подпапок `<пакет>\mods\` в порядке `Get-ChildItem` (по алфавиту).
- Дано pack.txt только с `version=1`, папки `mods\B`, `mods\A`. Тогда порядок модов пакета — `A`, `B`.

### INS-011 Замена папки мода целиком  [auto]
Для каждого мода пакета `N` установщик ДОЛЖЕН удалить `<root>\mods\N` (если есть, рекурсивно) и скопировать `<пакет>\mods\N` целиком; все операции с путями модов ДОЛЖНЫ использовать `-LiteralPath` (имена с `[`, `]` и др.). После установки множество файлов `<root>\mods\N` ДОЛЖНО равняться файлам пакета плюс маркер, содержимое — байт-в-байт.
- Дано в `<root>\mods\N` есть файл `old.script`, которого нет в пакете. Когда установка. Тогда `old.script` отсутствует.
- Дано мод с именем `zz Fix [test]`. Когда установка. Тогда папка заменена корректно.

### INS-012 Маркер  [auto]
В каждую установленную папку мода ДОЛЖЕН записываться `xrrfix_pack.txt` с текстом `xrRazom fixes pack <version>` (UTF-8 с BOM, `Set-Content`), и выводиться `  установлен: <N>`.
- Дано version=`2026.10.13-7`. Тогда маркер содержит `xrRazom fixes pack 2026.10.13-7`.

### INS-013 Папка разделителя  [auto]
Если `<root>\mods\<section>_separator` не существует, установщик ДОЛЖЕН создать её с `meta.ini` из строк `[General]`, `modid=0`, `version=`, `newestVersion=`, `category=0`, `installationFile=` (CRLF); существующую папку разделителя НЕ ДОЛЖЕН изменять.
- Дано папки разделителя нет. Тогда после установки есть `meta.ini` с секцией `[General]`.

### INS-014 Выбор профиля  [auto]
Профиль ДОЛЖЕН определяться как `-Profile`, если задан, иначе как значение строки `selected_profile=` из `<root>\ModOrganizer.ini` с удалёнными префиксом `@ByteArray(` и конечной `)`; modlist — `<root>\profiles\<профиль>\modlist.txt`. `ModOrganizer.ini` читается всегда (его отсутствие — код 1).
- Дано `selected_profile=@ByteArray(G.A.M.M.A)`. Тогда используется `profiles\G.A.M.M.A\modlist.txt`.
- Дано `-Profile Test`. Тогда используется `profiles\Test\modlist.txt` независимо от ini.

### INS-015 Бэкап modlist  [auto]
Перед изменением modlist.txt установщик ДОЛЖЕН копировать его в `modlist.txt.xrrfix.bak` рядом, перезаписывая прежний бэкап.
- Дано установка выполнена дважды. Тогда бэкап равен modlist.txt после первой установки.

### INS-016 Поиск разделителя и границ секции  [auto]
Строкой разделителя ДОЛЖНА считаться первая строка длиной > 1, у которой текст после первого символа равен `<section>_separator` (сравнение `-eq`, без учёта регистра; префикс `+`/`-` любой). Строки секции — строки над ней до ближайшей выше строки, начинающейся с `#` или оканчивающейся на `_separator` (не включая её).
- Дано `#hdr`, `+X`, `-Other_separator`, `+A`, `+B`, `-xrRazom Sync_separator`. Тогда строки секции — `+A`, `+B`; `+X` — над секцией.

### INS-017 Моды пакета — вверху секции, включены, в порядке пакета  [auto]
Пересобранная секция ДОЛЖНА начинаться с `+<имя>` каждого мода пакета в порядке пакета; каждая другая строка modlist с именем мода пакета (в любом месте, включённая или выключенная, в т.ч. дубликаты) ДОЛЖНА удаляться.
- Дано мод пакета `P` выключен (`-P`) в другой секции ниже. Тогда в результате ровно одна строка `+P` — в секции пакета.

### INS-018 Наши моды секции, которых нет в пакете  [auto]
Наш мод в строках секции, отсутствующий в пакете, ДОЛЖЕН оставаться в секции сразу после модов пакета (в исходном относительном порядке) в виде `-<имя>`; если он был включён — выводится «  выключен (нет в пакете): <имя>». Удалять его папку установщик НЕ ДОЛЖЕН.
- Дано в секции `+Old` с маркером, пакет без `Old`. Тогда секция: `+<моды пакета>`, `-Old`, `+<section>_separator`; папка `mods\Old` на месте.

### INS-019 Чужие моды в секции  [auto]
Чужой мод в строках секции ДОЛЖЕН переноситься сразу под строку разделителя (т.е. выводиться из секции) с сохранением исходной строки (состояние `+`/`-`) и относительного порядка; выводится «  перенесён из секции: <имя>». Выключать или удалять чужой мод установщик НЕ ДОЛЖЕН.
- Дано в секции `+Test Mod` без маркера. Тогда результат: `…, +xrRazom Sync_separator, +Test Mod, <прежние строки ниже разделителя>`.

### INS-020 Наши моды вне секции  [auto]
Включённый наш мод вне секции (включая легаси `zz xrRazom Fixes`), не входящий в пакет, ДОЛЖЕН выключаться на своём месте (`+N` → `-N`) с сообщением «  выключен старый фикс вне секции: <имя>»; выключенные — оставаться как есть.
- Дано `+zz xrRazom Fixes` в другой секции. Тогда на том же месте `-zz xrRazom Fixes`.

### INS-021 Чужие моды вне секции не меняются  [auto]
Строки чужих модов вне секции ДОЛЖНЫ сохраняться побайтно (включая префиксы, отличные от `+`/`-`, например `*`) и в исходном относительном порядке: строки над секцией — над ней, строки под разделителем — под ним (после перенесённых, INS-019).
- Дано 100 чужих строк до и после секции. Тогда их последовательности до и после блока секции не изменились.

### INS-022 Сборка итогового списка  [auto]
modlist.txt ДОЛЖЕН записываться как: все строки на `#` (в исходном порядке) → строки над секцией → `+<моды пакета>` → `-<оставшиеся наши моды секции>` → `+<section>_separator` → перенесённые чужие моды → строки под разделителем. Строка разделителя всегда пишется с `+`. Строки короче 2 символов (пустые) ДОЛЖНЫ отбрасываться.
- Дано modlist `# h`, `+F1`, `+P2`, `-Old`, `+Foreign`, `-xrRazom Sync_separator`, `+Below` (у Old есть маркер), пакет `[P1, P2]`, разделитель секции выше нет. Тогда результат: `# h`, `+P1`, `+P2`, `-Old`, `+xrRazom Sync_separator`, `+F1`, `+Foreign`, `+Below`.
  (Без другой границы выше секция начинается сразу после `# h`, поэтому `+F1` — чужой мод секции и переносится.)

### INS-023 Разделителя нет в modlist  [auto]
Если строки разделителя нет, блок секции (`+<моды пакета>`, `+<section>_separator`) ДОЛЖЕН вставляться сразу после строк-комментариев (высший приоритет), а все прочие строки — после него в исходном порядке (с применением INS-017 и INS-020).
- Дано `# h`, `+A`, `+B`. Пакет `[P]`. Тогда `# h`, `+P`, `+xrRazom Sync_separator`, `+A`, `+B`.

### INS-024 Нет modlist.txt  [auto]
Если modlist.txt выбранного профиля не существует, установщик ДОЛЖЕН вывести «Не найден <путь> - включите моды в MO2 вручную.», НЕ создавать modlist и бэкап, и завершиться с кодом 0 (моды уже скопированы).

### INS-025 Кодировка modlist  [auto]
modlist.txt ДОЛЖЕН читаться как UTF-8 и записываться `WriteAllLines` в UTF-8 без BOM с окончаниями строк CRLF (включая последнюю строку).
- Дано modlist с BOM и именем мода на кириллице. Тогда результат без BOM, имя сохранено побайтно.

### INS-026 Сообщения о результате  [manual]
После пересборки ДОЛЖНО выводиться «Профиль '<профиль>': секция '<section>' обновлена (копия: modlist.txt.xrrfix.bak)», в конце — «Готово: пакет <version> установлен.»

### INS-027 Идемпотентность  [auto]
Повторный запуск с тем же пакетом на результате предыдущего ДОЛЖЕН давать побайтно тот же modlist.txt и то же содержимое папок модов пакета.
- Дано установка выполнена. Когда она выполняется ещё раз. Тогда modlist.txt не изменился, код 0.

### INS-028 Неприкосновенность чужих модов  [auto]
Установщик НЕ ДОЛЖЕН удалять, перезаписывать или выключать папки и строки модов, не являющихся модами пакета или нашими модами; единственное допустимое изменение для чужого мода — перенос строки из секции под разделитель (INS-019).

### INS-029 Регистр имён  [auto]
Сопоставление имени строки modlist с модами пакета, легаси-списком и разделителем ДОЛЖНО выполняться без учёта регистра (PowerShell `-contains`/`-eq`), соответствуя файловой системе Windows.
- Дано пакет `zz Fix A`, в modlist `+ZZ fix a`. Тогда строка `+ZZ fix a` удаляется и заменяется `+zz Fix A`.

### INS-030 Обратная совместимость вызова  [auto]
Вызов `install.ps1 -NoWait` без других параметров (агент пира, архивы прошлых версий) ДОЛЖЕН работать с поиском корня (INS-004) и активным профилем (INS-014).

## Ошибки и граничные случаи
- Сбой посреди копирования модов (нет `<пакет>\mods\N`, занят файл) оставляет уже заменённые моды новыми, текущий — удалённым, modlist — неизменённым; код 1. Повторный запуск исправляет.
- Отсутствующий `ModOrganizer.ini` проявляется после копирования модов (код 1, modlist не тронут).
- Строки `#` в середине modlist переносятся в начало файла; пустые строки исчезают.
- Если секция пуста и сразу над разделителем стоит другой разделитель, строки секции пусты, а моды пакета вставляются над разделителем.
- Наш мод, у которого папка удалена (маркера нет), считается чужим и при нахождении в секции переносится под разделитель.

## Открытые вопросы / известные ограничения
1. **`install.bat` не передаёт аргументы и коды выхода**: `%*` не пробрасывается, итоговый код bat — код `pause` (0). Агент и publish вызывают `install.ps1` напрямую.
2. **Сохранение корня до проверки процессов** (INS-005): при выходе с кодом 2 `gamma_root.txt` уже перезаписан — расходится с «ничего не меняет» из CONTRACT.md.
3. **Пустой `gamma_root.txt`**: `(Get-Content … | Select -First 1).Trim()` на `$null` — исключение, установщик падает (код 1) вместо перехода к поиску.
4. **Диалог выбора папки в фоне**: агент из Планировщика вызывает установщик без `-GammaRoot`; если корень не найден автоматически, `FolderBrowserDialog` блокирует фоновый процесс до таймаута агента.
5. **Игра по умолчанию не блокирует**: список по умолчанию — только `ModOrganizer`, хотя сообщение просит закрыть и игру (publish.ps1 по контракту блокирует и `Anomaly*`).
6. **Не `-LiteralPath` в части путей**: `Test-Root`, `Test-Path $modlist`, копия бэкапа и `gamma_root.txt` используют `-Path` — корень/профиль с `[`/`]` в имени не будет найден/обработан.
7. **`-GammaRoot C:\`** превращается в `C:` (TrimEnd), то есть в путь относительно текущей папки диска.
8. **Строка разделителя всегда `+`**, тогда как MO2 сам пишет разделители как `-…_separator`; MO2 принимает оба варианта, но первый запуск меняет строку.
9. **Несколько строк `selected_profile=`** или `version=`/`section=` в pack.txt дают массив и некорректный путь/текст; profile с не-ASCII в `@ByteArray(...)` (экранирование MO2) не декодируется. Профиль не найден → INS-024, код 0 — для агента это «успех» без включения модов.
10. **Строка-комментарий `#<section>_separator`** формально распознаётся как разделитель (проверяется текст после первого символа).
11. **Неатомарность**: замена папок и запись modlist не транзакционны; бэкап хранит только одну предыдущую версию.
12. Имена модов из pack.txt не проверяются на `..`/`\` — безопасность опирается на проверку CI (CI-007) и на `publish.ps1`.
