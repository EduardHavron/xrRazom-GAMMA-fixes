# FX-BELT: память пояса Remember Outfit Belt у пира
Статус: действует        Проверка в игре: не записана        Мод: `zz xrRazom Fix - Remember Belt`        Скрипт: `gamedata/scripts/zz_xrrfix_remember_belt.script`
Где ставить: оба (хост и каждый пир)        Зависит от: xrRazom Co-op 1.4 (`xrr_peer_mdata.register`), G_FLAT's Remember Belt Items (`remember_outfit_belt`)        Лог-маркер: `[XRRFIX] belt: beltMemory registered as peer m_data, save_belt guarded`

## Проблема
У пира после переподключения пропадает память пояса у всех костюмов (и надетого, и лежащих в рюкзаке): при надевании
костюма артефакты больше не возвращаются на пояс. Иногда память остаётся, но неполная — только часть артефактов.

## Причина
- Мод (`G_FLAT's Remember Belt Items/.../remember_outfit_belt.script`) хранит `belt_memory[outfit_id] = { items = { [item_id] = true }, date }`,
  публикует её в `save_state` как `m_data.beltMemory`, читает в `load_state`. Запись — `save_belt(outfit)` из
  `actor_item_to_belt` и `actor_item_to_ruck` (вызов по имени глобала модуля, т.е. через таблицу модуля).
- Пир никогда не сохраняется. Его собственные ключи `m_data` между сессиями переносит только `xrr_peer_mdata` по своему
  `manifest` (`xrr_peer_mdata.script`): хост хранит их за пира, при входе `xrr_peer_mdata_apply` кладёт их в `m_data`
  и запускает `load_state`. `beltMemory` в манифесте нет → после входа у мода пустая память.
- При входе xrRazom восстанавливает инвентарь пира, предметы по одному встают на пояс/в рюкзак; срабатывают
  `actor_item_to_belt`/`actor_item_to_ruck`, и `save_belt` перезаписывает память надетого костюма частичным поясом
  [НЕ ПРОВЕРЕНО] (по истории и наблюдениям; порядок восстановления — в C++).
- Ключи `beltMemory` — числовые id. Канал m_data кодируется движком; фикс на всякий случай приводит ключи к числам
  [НЕ ПРОВЕРЕНО] (что они могут прийти строками — предположение, в Lua не проверяется).

## Решение
В `on_game_start` (под `pcall`):
1. Регистрирует `actor_on_first_update`: если идёт сессия (`XrrIsConnected()` или `XrrIsHosted()`), выставляет
   `grace_until = time_global() + 10000`.
2. Если есть `remember_outfit_belt.save_belt` и `xrr_peer_mdata.register`:
   - `xrr_peer_mdata.register("beltMemory")` — ключ переносится целиком (без `subs`); вызов в `on_game_start`, как требует xrRazom;
   - `remember_outfit_belt.save_belt` оборачивается: пока `time_global() < grace_until`, вызов игнорируется;
   - регистрирует `load_state`: `normalize(m_data.beltMemory)` под `pcall` — на месте (та же таблица, что держит мод):
     ключи костюмов → числа, нечисловые/нетабличные записи удаляются, `items` → `{ [число] = true }`, нетабличные `items` → `{}`,
     `date` → число или 0; при переименовании ключей — лог `belt: <n> outfit key(s) normalized`.

## Требования
### FX-BELT-001 beltMemory в манифесте пира  [auto]
При наличии мода и xrRazom ключ `beltMemory` ДОЛЖЕН быть добавлен в `xrr_peer_mdata.manifest` ровно один раз.
- Дано заглушка `remember_outfit_belt = { save_belt = f }`, реальная `xrr_peer_mdata.register`
  Когда `on_game_start` фикса вызван (в т.ч. дважды)
  Тогда `beltMemory` встречается в `manifest` один раз, `sub_filter.beltMemory == nil`.

### FX-BELT-002 Нормализация ключей  [auto]
`load_state` ДОЛЖЕН привести память к виду `{ [number] = { items = { [number] = true }, date = number } }`, не меняя идентичность таблицы.
- Дано `m = { beltMemory = { ["101"] = { items = { ["5"] = true, [6] = true }, date = "12.5" }, bad = 1, [7] = "x" } }`
  Когда вызывается обработчик `load_state(m)`
  Тогда `m.beltMemory` — та же таблица; `m.beltMemory[101].items == { [5] = true, [6] = true }`, `date == 12.5`;
  ключей `"101"`, `bad`, `7` нет; лог `belt: 1 outfit key(s) normalized`.

### FX-BELT-003 Пауза записи после входа  [auto]
В течение 10 с после первого апдейта в сессии `save_belt` НЕ ДОЛЖНА изменять память; после — ДОЛЖНА работать как в оригинале.
- Дано сессия активна, `actor_on_first_update` в момент T
  Когда `save_belt(outfit)` вызывается в T+5000 и в T+10001
  Тогда первый вызов не дошёл до оригинала, второй — дошёл.
- Дано соло (сессии нет)
  Тогда `grace_until` не выставляется, все вызовы идут в оригинал.

### FX-BELT-004 Память всех костюмов переживает переподключение  [manual]
Память пояса пира — и надетого костюма, и костюмов в рюкзаке — ДОЛЖНА сохраняться между подключениями.
- Дано пир настроил пояс на костюме A (надет) и B (в рюкзаке, ранее надевался с артефактами)
  Когда пир отключается и подключается снова, затем надевает B
  Тогда артефакты B возвращаются на пояс, у A пояс тот же, что был до выхода.

### FX-BELT-005 Восстановление инвентаря не портит память  [manual]
Восстановление инвентаря при входе НЕ ДОЛЖНО перезаписывать память надетого костюма частичным поясом.
- Дано у надетого костюма в памяти 5 артефактов
  Когда пир подключается, xrRazom восстанавливает инвентарь, и через >10 с пир снимает и снова надевает костюм
  Тогда на пояс возвращаются все 5 артефактов.

## Безопасность
- Нет Remember Belt — лог `belt: Remember Outfit Belt not installed, skipped`; нет `xrr_peer_mdata.register` —
  `belt: xrr_peer_mdata.register missing, skipped`. Колбэк паузы при этом всё равно регистрируется, но оборачивать нечего.
- Соло: `grace_until` не выставляется; регистрация в манифесте ни на что не влияет (манифест читает только движок в сессии);
  нормализация на корректных данных ничего не меняет.
- Хост: тоже получает 10 с паузы после первого апдейта, если `XrrIsHosted()` к этому моменту уже истинно
  (в xrr_core указано, что на `on_game_start` оно ещё ложно; к первому апдейту — [НЕ ПРОВЕРЕНО]).
- Повторная установка: `register` идемпотентен; повторная обёртка `save_belt` и повторная регистрация `load_state`
  (новые замыкания) безвредны.

## Вне области / известные ограничения
- Пауза — фиксированные 10 с от `actor_on_first_update`. Если восстановление инвентаря дольше, частичная запись возможна;
  все изменения пояса самим игроком в эти 10 с тоже не запоминаются.
- Пауза не закрывает `memory_size_control()` в `actor_item_to_belt`: при входе с костюмом, которого нет в памяти, мод может
  удалить самую старую запись (лимит `memory_limit`, по умолчанию 5).
- Память, потерянная до установки фикса, не восстанавливается.
- id предметов в памяти — общие id хоста; если предмет пересоздан с новым id, мод его не найдёт (как и в соло).

## Проверка в игре
1. Хост и пир запускают игру. Лог обоих: `[XRRFIX] belt: beltMemory registered as peer m_data, save_belt guarded`.
2. Пир надевает костюм A, кладёт артефакты на пояс; надевает костюм B с другим набором; снова A.
3. Пир отключается и подключается снова; ждёт >10 с.
4. Пир надевает B — артефакты B на поясе; надевает A — артефакты A на поясе.
5. Если в логе есть `[XRRFIX] belt: N outfit key(s) normalized` — ключи пришли строками и были исправлены (информативно).
