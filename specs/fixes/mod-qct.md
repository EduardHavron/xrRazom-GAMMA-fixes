# MOD-QCT: Quantity Craft and Transfer — «Сколько?» для крафта, переноса и передачи
Статус: черновик        Проверка в игре: не проводилась        Мод: `Quantity Craft and Transfer`        Скрипты: `gamedata/scripts/qct_main.script`, `gamedata/scripts/qct_dialog.script`, `gamedata/scripts/qct_mcm.script`, интерфейс: `gamedata/configs/ui/ui_qct_dialog.xml`, строки: `gamedata/configs/text/{eng,rus}/st_qct.xml`
Где ставить: оба (через секцию «xrRazom Sync»; работает и в соло, передача игроку — только в коопе)        Зависит от: Serious Workshop optimization (`ui_workshop.UIWorkshopCraft`), Craft From Stashes, Keep Crafting Window Open (действующий `Craft`), Tronex `ui_inventory`, MCM, xrRazom (`XrrPlayers`, `XrrNet`) — все необязательны        Лог-маркер: `[QCT] workshop: batch crafting installed`, `[QCT] inventory: move quantity installed`

Собственный мод (не фикс): диалог «Сколько?» в стиле Fallout: New Vegas — ползунок, поле ручного ввода, `-`/`+`,
«Макс.», «ОК», «Отмена» — для трёх действий:
- **крафт** в мастерской: рецепт N раз одним запросом;
- **перенос** в тайнике / трупе / компаньоне и в окне торговли: N предметов стопки;
- **передача** игроку xrRazom из своего инвентаря: N предметов стопки.

Открывается из контекстного меню (ПКМ) или хоткеем из MCM; хоткей — клавиша плюс любое сочетание Ctrl/Shift/Alt.

## Проблема
- Чтобы скрафтить много одинаковых предметов, приходится много раз нажимать «Крафт».
- Из стопки можно перенести либо один предмет, либо всю стопку («Переместить всё»); выбрать количество нельзя.
- То же со штатной передачей xrRazom «Отправить <Ник>»: один предмет на одно нажатие.
- Нужно, чтобы при крафте сначала брались предметы в худшем состоянии, а при переносе и передаче — в лучшем.

## Причина
Штатных средств для количества нет:
- `ui_workshop.UIWorkshopCraft:Craft` (действующая версия — `471- Craft From Stashes/zz_ui_workshop_keep_crafting_window_open.script`)
  крафтит то, что `UpdateItem` выбрал для одного рецепта.
- В `ui_inventory.UIInventory.properties` есть только `move` (один) и `move_all` (вся стопка) — `G.A.M.M.A. Accurate Defense Values/ui_inventory.script`.
- `xrr_patch_inventory.script` добавляет «Отправить <Ник>»: один `XrrPlayers():SendGiveItem(netid, id)` на нажатие.

Найдено по ходу разбора (в стоковом коде, не в этом моде):
- Цикл выбора материалов в `UpdateItem` (`zzzz_serious_ui_workshop.script`, повторён в Craft From Stashes) недосписывает
  многоразовые материалы, когда складываются несколько частично использованных предметов: `dischargeAmount` уменьшается на
  накопленную сумму, а не на использования предмета. Пример: нужно 3, предметы на 1, 1 и 5 использований — списывается 2.
- `alife_release` не убирает клиентский объект мгновенно: до обработки события удаления `level.object_by_id` ещё
  возвращает его [НЕ ПРОВЕРЕНО — поведение движка; у пира xrRazom удаление идёт через хост]. Повторная оценка рецепта в
  этот момент выбрала бы уже списанный предмет, а его второе удаление (`alife_release_id` без серверного объекта) ничего не
  списывает — дюп. Поэтому крафт идёт одним вызовом `Craft`, а следующий — только после реального исчезновения потраченного.

## Решение
Патчи ставятся в `actor_on_first_update` (после всех `on_game_start`, где цепочку `UpdateItem`/`Craft` собирают
Serious Workshop, Craft From Stashes и FX-WSAMMO), один раз на класс (`__qct_wrapped`).

**Крафт (`ui_workshop.UIWorkshopCraft`).**
- ПКМ по рецепту (`On_CC_Mouse2`) → пункт «Скрафтить несколько...»; хоткей — для рецепта под курсором или выбранного.
- Максимум в диалоге — точный: рецепт оценивается штатной цепочкой `UpdateItem` с количеством каждого материала ×N
  (тайники Craft From Stashes, исключение пояса, неполные коробки, FX-WSAMMO); наибольшее N ищется бинарным поиском от
  оценки сверху (`craft_max`: материалы в инвентаре, тайнике мастерской и тайниках в радиусе Craft From Stashes; ограничение
  MCM `craft_cap`). После этого показывается обычный вид рецепта на один крафт.
- ОК → то же вычисление на момент нажатия (количество урезается до доступного) → один вызов `Craft()` с
  `craft_item_r[2] = N`: `Craft` списывает N наборов (`craft_use_low_cond` — худшее состояние первым) и создаёт N результатов.
- Пока идёт вызов, временно обёрнуты `alife_release`, `alife_create_item`, `utils_item.discharge`:
  - записываются удалённые id и ожидаемые остатки использований;
  - результат-патроны: `Craft` создал бы одну коробку на N·box патронов — создаётся N коробок по `box`;
  - результат `*_lead_box`: `Craft` возвращает «потрачено свинцовых контейнеров − 1» — при N результатах лишние N−1 не создаются;
  - статистика `items_crafted` добавляется до N.
- У пира xrRazom вызов идёт внутри `XrrNet():SetPeerChainWindow(true/false)` — как кнопка «Крафт» в `xrr_patch_workshop.script`.
- Новая пачка (диалог, ПКМ) не начинается, пока всё удалённое прошлой пачкой не исчезло, а разряженное не дошло до
  ожидаемых использований; таймаут 4 с (в коопе 15 с) — после него сообщение «проверьте инвентарь».
- `UpdateItem` дополнительно: для многоразовых неизнашиваемых материалов выбор пересобирается — сначала с меньшим числом
  использований, списание ровно `amount` (исправляет недосписание, см. «Причина»).

**Перенос (`ui_inventory.UIInventory`, режимы `loot` и `trade`).**
- Пункт «Переместить несколько...» (после «Переместить всё») на стопке (`Cond_Childs`, `Cond_Move`); хоткей — стопка под курсором.
- Порядок — лучшие первыми: патроны по числу патронов, многоразовые по использованиям, остальные по состоянию.
- ОК: стопка перепроверяется — предмет всё ещё в исходном контейнере (индекс ячеек; в `loot` — и владелец), `Cond_Move`;
  перенос штатным `Action_Move`, каждый id не больше одного раза.
- Для предметов-пачек (`IsAmmo`) диалог показывает штуки: «В стопке: 290 шт. — будет перенесено: 30 шт.»; ползунок — по пачкам.

**Передача игроку (xrRazom, режим `inventory`).**
- Пункты «Передать несколько: <Ник>» после «Отправить <Ник>» xrRazom; игроки — по тем же правилам: живой аватар в 5 м, до 8,
  ближайшие первыми. Хоткей в своём инвентаре — ближайшему игроку. Квестовые предметы не предлагаются.
- ОК: отбор лучших N, каждый ещё у актёра; отправка по одному `SendGiveItem` раз в 50 мс (очередь тикает в
  `actor_on_update` и в `UIInventory:Update`); перед каждой отправкой — предмет ещё у актёра, той же секции, не отправлялся,
  получатель ещё в 5 м. Иначе — остановка с сообщением «Передано игроку X: k из N».

**Диалог (`qct_dialog.script`, `ui_qct_dialog.xml`).**
- 3t-кнопки и поле ввода рисуют текстуру по размеру из XML и не меняют её по `SetWndSize` (видно на скриншоте 16:9:
  кнопки шире панели) [НЕ ПРОВЕРЕНО — вывод по скриншоту, не по коду движка]. Поэтому в XML три набора элементов с готовыми
  ширинами (4:3, 16:9 — `_16`, 21:9 — `_21`), скрипт берёт ближайший к соотношению сторон экрана и раскладывает по нему.
- Ввод: ползунок и поле синхронны; неверный текст при ОК не закрывает диалог; Enter/Esc/стрелки/Home/End.

**MCM (`qct_mcm.script`, `qct/...`).** `key` (по умолчанию Y), `mod_ctrl`/`mod_shift`/`mod_alt` (по умолчанию Alt),
`ctx_craft`, `ctx_move`, `ctx_give`, `start_max`, `craft_cap` (1..500, 100). Хоткей срабатывает при точном совпадении
модификаторов: отмеченные зажаты, неотмеченные нет.

## Требования

### MOD-QCT-001 Однократная установка  [auto]
Патчи мастерской и инвентаря ДОЛЖНЫ ставиться в `actor_on_first_update` один раз на класс с лог-маркером; без класса —
строка в лог и пропуск.
- Дано `ui_workshop.UIWorkshopCraft` есть. Когда `actor_on_first_update` дважды. Тогда маркер `[QCT] workshop: batch crafting installed` один раз.
- Дано `ui_inventory` нет. Когда `actor_on_first_update`. Тогда `[QCT] inventory: UIInventory missing, skipped`, без ошибки.

### MOD-QCT-002 Хоткей с точными модификаторами  [auto]
Хоткей ДОЛЖЕН срабатывать только при нажатой клавише из MCM и точном совпадении Ctrl/Shift/Alt; клавиша ≤ 0 — выключено.
- Дано key = Y, mod_ctrl и mod_shift. Когда Y с Ctrl+Shift. Тогда срабатывает. Когда Y с Ctrl. Тогда нет. Когда Y с Ctrl+Shift+Alt. Тогда нет.
- Дано настройки по умолчанию (Alt+Y). Когда Y без модификаторов. Тогда нет; Alt+Y — да.

### MOD-QCT-003 Точный максимум крафта  [auto]
Максимум в диалоге ДОЛЖЕН быть наибольшим N, при котором штатная оценка с материалами ×N разрешает крафт (не больше
`craft_cap`); после открытия диалога состояние рецепта — обычное, на один крафт.
- Дано 11 материалов, рецепт требует 2. Когда открыт диалог. Тогда max = 5, `craft_item[1]` — 2 id.

### MOD-QCT-004 Один вызов Craft на N крафтов  [auto]
ОК с N ДОЛЖЕН приводить ровно к одному вызову `Craft()`, который списывает N наборов и создаёт N результатов.
- Дано 11 материалов по 2. Когда ОК 5. Тогда 1 вызов `Craft`, 5 результатов, остался 1 материал, ни один id не удалён дважды.

### MOD-QCT-005 Перепроверка при ОК  [auto]
При ОК количество ДОЛЖНО пересчитываться по текущему состоянию и урезаться до доступного; если рецепт сменился — ничего.
- Дано диалог открыт с max 3, затем 2 материала исчезли. Когда ОК 3. Тогда скрафчено 2, потрачено 4 материала.

### MOD-QCT-006 Патроны-результат нормальными коробками  [auto]
Для результата-патронов ДОЛЖНО создаваться N коробок по `box` патронов, а не одна на N·box.
- Дано результат с box = 10. Когда ОК 3. Тогда три создания с `ammo = 10`; подсказка диалога показывает штуки.

### MOD-QCT-007 Возврат свинцовых контейнеров  [auto]
Для результата `*_lead_box` возврат контейнеров НЕ ДОЛЖЕН превышать возврат N отдельных крафтов (0 на крафт).
- Дано рецепт из `lead_box` и артефакта, результат `af_x_lead_box`. Когда ОК 3. Тогда 3 результата и 0 созданных `lead_box`.

### MOD-QCT-008 Следующая пачка после реального удаления  [auto]
Новая пачка НЕ ДОЛЖНА начинаться, пока удалённые прошлой пачкой объекты ещё видны; после таймаута — предупреждение.
- Дано удаление не подтверждается. Когда сразу открыть диалог снова. Тогда диалога нет, сообщение `st_qct_wait`; повторных удалений нет.
- Когда прошло больше 4 с. Тогда в окне `st_qct_warn_sync`.

### MOD-QCT-009 Многоразовые материалы: меньше использований первым, точное списание  [auto]
Для многоразового неизнашиваемого материала выбор ДОЛЖЕН идти по возрастанию использований и списывать ровно нужное.
- Дано предметы на 1, 1, 3, 2 использования, рецепт требует 3. Когда ОК 2. Тогда 2 результата, остаток — 1 использование.

### MOD-QCT-010 Перенос N: лучшие первыми, перепроверка, штуки  [auto]
Перенос ДОЛЖЕН брать N лучших предметов, ещё лежащих в исходном контейнере; для пачек диалог считает штуки.
- Дано стопка пачек 4, 10, 7, 10 патронов. Когда диалог. Тогда max 4, для 3 — «31 / 27».
- Дано одна пачка на 10 ушла из рюкзака до ОК. Когда ОК 2. Тогда перенесены 10 и 7.

### MOD-QCT-011 Передача N игроку xrRazom  [auto]
Передача ДОЛЖНА отправлять N лучших предметов, ещё принадлежащих актёру, по одному `SendGiveItem` на id, не больше одного
раза, и останавливаться, если получатель дальше 5 м.
- Дано стопка 0.5/0.9/0.7/0.8, предмет 0.9 ушёл до ОК. Когда ОК 3. Тогда отправлены 0.8, 0.7, 0.5.
- Дано получатель отошёл на 10 м после первой отправки. Тогда отправлен 1 предмет.

### MOD-QCT-012 Без коопа нет пунктов передачи  [auto]
Пункты «Передать несколько» НЕ ДОЛЖНЫ появляться без xrRazom или без игроков в 5 м.
- Дано нет `XrrPlayers`. Когда `refresh_peers`. Тогда список пуст.

### MOD-QCT-013 Крафт пира в окне peer chain  [auto]
У пира xrRazom вызов `Craft` ДОЛЖЕН идти между `SetPeerChainWindow(true)` и `SetPeerChainWindow(false)`.
- Дано `XrrIsHost() == false`. Когда ОК. Тогда `Craft` вызван при открытом окне, после — окно закрыто.

### MOD-QCT-014 Вид диалога  [manual]
Все элементы диалога ДОЛЖНЫ быть внутри панели на 4:3, 16:9 и 21:9.

### MOD-QCT-015 Кооп: крафт и передача у пира  [manual]
У пира пачка крафта и передача ДОЛЖНЫ давать одинаковые количества у хоста и пира, без дюпов.

## Безопасность
- Без Serious Workshop / Craft From Stashes / `ui_inventory` соответствующая часть не ставится (лог, MOD-QCT-001); без MCM — значения по умолчанию.
- В соло пункты передачи не появляются; `XrrNet` не вызывается без функций xrRazom.
- Обёртки `alife_release` / `alife_create_item` / `utils_item.discharge` живут только на время одного `Craft()` и
  восстанавливаются и при ошибке (`pcall`).
- Одиночный крафт кнопкой не меняется, кроме исправленного выбора многоразовых материалов.

## Вне области / известные ограничения
- Для рецептов «артефакт → артефакт» качество результатов — среднее по всем потраченным артефактам пачки, а не по каждому
  крафту отдельно (так считает `Craft` при одном вызове).
- Опция Craft From Stashes «Use best artefact for craft» (по умолчанию включена) берёт лучшие артефакты, а не худшие.
- `craft_use_low_cond` в Craft From Stashes при повторном выборе изнашиваемых материалов не исключает пояс — стоковая
  проблема, не этого мода.
- Если цепочка `Craft` создаёт результат не через `alife_create_item`, отчёт покажет «скрафчено 0» [НЕ ПРОВЕРЕНО].
- Передача: подтверждение получения от xrRazom не ждём; каждый id отправляется один раз, дальше — логика `SendGiveItem` движка.

## Проверка в игре

2. Мастерская: ПКМ по рецепту → «Скрафтить несколько...», N из рюкзака и из соседнего тайника; рецепт с патронами-результатом
   (N коробок); в логе `[QCT] craft <секция>: asked N, crafted N in one request`.
3. Тайник: «Переместить несколько...» на стопке патронов — штуки в подсказке, лучшие первыми.

   остановка; в логе `[QCT] give ...`.
5. Хоткей с двумя модификаторами; вид диалога на широком экране.
